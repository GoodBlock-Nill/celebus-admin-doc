# 디자인 개선 의뢰서 — 팬스테이지(FanStage)

> 이 문서는 외부 디자이너(사람 또는 AI)에게 그대로 전달하는 **디자인 개선 의뢰 프롬프트**입니다.
> 함께 전달할 참고 자료는 `fanstage-design-reference.md`를 보세요.

---

당신은 K-pop 팬덤 서비스를 전문으로 하는 **시니어 프로덕트 디자이너**입니다.
아래 서비스의 UI/UX를 **정보구조 · 화면설계 · 디자인 시스템** 관점에서 개선 제안해 주세요.
결과물은 "즉시 개발 착수 가능한 수준"의 구체적 산출물이어야 합니다.

## 1. 서비스 한 줄 정의

팬이 직접 찍은 아티스트 영상(직캠·커버·편집)을 올려 **최애 멤버에게 자랑**하고,
**멤버가 실제로 그 영상을 보고 반응(하트·댓글)** 해주는 팬 콘텐츠 앱.

> 핵심 감정: **"내 영상을 멤버가 봐줬다"는 자부심.**

## 2. 타깃 & 원칙

- 사용자: 10~20대 K-pop 팬덤, **100% 모바일(PWA)**.
- 팬덤에게 익숙한 **틱톡 · 유튜브 · 인스타** 패턴 기반 — 보기 편하고, 올리기 편하고, 평가하기 편하게.
- 감정 연출(멤버 반응)은 **절제**된 톤. 과한 글로우 · 컨페티 금지.
- 타이틀은 "팬스테이지"로 고정하되, **'무대/극장' 은유에 갇히지 말 것** — 실제 감각은 소셜 콘텐츠 공유.

## 3. 핵심 정보구조 (★ 개선 과제의 핵심)

콘텐츠는 **관리자가 생성한 "스테이지" 단위**로 조직됩니다.

- **스테이지 = 특정 공연/이벤트의 영상 아카이브** (예: "2026 여름 부산 버스킹", "홍대 라이브 클럽 0628").
  관리자가 스테이지를 먼저 만들고, 팬은 그 공연에 맞는 자기 영상을 **해당 스테이지에** 업로드합니다.
  → 즉 **영상은 항상 "어느 공연"에 속합니다.** 공연별 카테고리화가 서비스의 뼈대입니다.
- 스테이지 안에서 영상은 카테고리(직캠 / 커버 / 편집 / 기타)로 다시 나뉩니다.
- 그 외 개념:
  - **멤버 하트** — 멤버가 영상을 보고 남기는 반응(서비스의 심장).
  - **그랜드슬램** — 멤버 전원이 하트를 남긴 영상.
  - **댓글** — 멤버 댓글은 특별 표시.
  - **월드컵 이벤트** — 스테이지 영상들로 겨루는 인기투표 토너먼트(이상형 월드컵 형식).
  - **명예의 전당** — 멤버 하트를 많이 받은 영상 모음.
  - **마이페이지** — 내 영상 · 멤버가 봐준 영상 · 내 댓글.

## 4. 우리가 겪는 문제 (해결 요청)

1. **스테이지(공연)별로 보기가 불편하다** — 모든 영상을 한 피드에 섞으니 "이 공연 영상만 모아보기"가 안 됨.
   공연별 아카이브 구조를 살리면서도 둘러보기가 매끄러운 정보구조가 필요.
2. **필터가 너무 많다** — 공연 · 카테고리 · 인기 등 필터가 난립. 탐색 부담을 줄여야 함.
3. 초기 디자인이 지루하고 밀도가 낮았음(빈 카드, 스크롤 피로).
4. 멤버 반응(서비스의 심장)이 눈에 잘 안 띄었음.

## 5. 이미 폐기한 방향 (반복 제안 금지)

- ❌ 다크 배경 + 네온 글로우 + 보라→핑크→골드 그라데 = **전형적 '공장형 AI 디자인'**.
- ❌ '극장 / 무대 / 스포트라이트' 은유를 앱 전체에 씌우는 방향.
- ✅ 확정 톤: **밝은(라이트) 클린 콘텐츠 앱** + 절제된 포인트 컬러(일렉트릭 인디고 계열, 브랜드 보라 계승).

## 6. 요청 산출물

아래를 **구체적으로** 제안해 주세요.

| 항목 | 내용 |
|------|------|
| **A. 정보구조(IA)** | 스테이지(공연) 컨테이너와 개별 영상 탐색을 어떻게 화면으로 조화시킬지. 대안 2~3개 + 각 장단점 (예: 스테이지 허브→상세→몰입 / 통합 피드+공연 렌즈 / 하이브리드) |
| **B. 내비게이션·필터 최소화** | 필수 필터만 남기는 원칙과 배치. 하단 탭 구성 |
| **C. 화면별 레이아웃** | 와이어프레임 수준: 홈, 스테이지 목록/상세, 영상 몰입 재생, 올리기 플로우, 마이페이지, 명예의 전당, 월드컵 이벤트 |
| **D. 멤버 반응의 '절제된' 표현안** | 피드 배지 · 상세 화면 · 알림에서 어떻게 보여줄지 |
| **E. 디자인 시스템** | 컬러 토큰, 타이포 스케일, 카드·칩·버튼·시트 컴포넌트 규격, 간격/라운드 원칙 |
| **F. 근거** | 각 제안이 왜 팬덤 사용성에 맞는지 |

## 7. 제약

- 모바일 우선(약 390~430px). **하단 탭 내비게이션** 사용.
- 영상은 **외부 링크(유튜브 / 틱톡 / 인스타) 임베드** 방식. 자체 업로드 아님(링크 붙여넣기).
- 다국어(한 / 영 / 일) 대응.
- **로그인 없이 열람 가능**, 상호작용(하트 · 댓글 · 업로드 · 마이)만 로그인 필요.
- 산출물은 텍스트 설명 + 필요 시 ASCII 와이어프레임 또는 HTML/CSS 목업으로.
