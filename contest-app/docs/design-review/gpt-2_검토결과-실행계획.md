# CELEBUS MOMENT
## 디자인 검토 결과 및 실행 계획

**수신:** Claude Code Agent Team — 개발 · 기획 · 디자이너  
**문서 목적:** CELEBUS MOMENT 디자인 리뷰 덱과 제품 디자인 패킷을 바탕으로, 배포·SSO 연동 전 단계에서 확정해야 할 디자인·기획·개발 작업을 실행 가능한 티켓 수준으로 정리한다.  
**검토 기준:** `CELEBUS MOMENT · Design Review.html` 최신본과 함께 전달된 서비스 컨셉·데이터 모델·화면 명세  
**검토 범위:** 디자인 시스템, 브랜딩, IA, 사용자 플로우, 멤버 반응 표현, 화면 디테일, 상태 설계  
**이번 검토에서 제외:** 보안·운영·배포·SSO 구현 자체. 단, 해당 영역과 연결되는 UX 요구사항은 기록한다.

## 1. Executive Summary

CELEBUS MOMENT의 핵심 경쟁력은 일반 팬 콘텐츠 SNS가 아니라 다음 경험이다.

> **팬이 올린 순간을 실제 아티스트 멤버가 보고 반응했다는 경험**

현재 방향은 유지한다.

- 라이트·뉴트럴 UI
- CELEBUS 바이올렛 포인트 컬러
- 공연별 콘텐츠 아카이브
- 로그인 없이 열람, 상호작용만 로그인
- 외부 영상 임베드
- 멤버 반응을 절제된 배지·아바타로 표현
- 홈 · 공연 · ＋ · 이벤트 · 마이 하단 탭

다만 최신 리뷰 덱에서 문서 원칙과 실제 목업 사이에 다음 불일치가 확인되었다.

1. **그라데이션 사용 규칙과 실제 화면이 다르다.**
2. **‘스테이지’ 용어가 폐기된 무대 은유와 함께 핵심 UI에 남아 있다.**
3. **화면 인벤토리의 ‘구현 완료’ 표기와 실제 시각적으로 검토 가능한 화면 범위가 다르다.**
4. **멤버가 ‘봤다’는 상태, 하트, 댓글의 의미가 데이터·카피·컴포넌트에서 완전히 분리되어 있지 않다.**
5. **업로드 이후 멤버 반응까지의 대기 상태와 알림 복귀 플로우가 명시적으로 설계되지 않았다.**

### 최우선 결정

| 우선순위 | 결정/작업 | 담당 협업 |
|---|---|---|
| P0-1 | 브랜드 그라데이션 적용 대상 확정 및 실제 UI·문서 일치 | 기획 + 디자인 + 개발 |
| P0-2 | 사용자 UI 용어를 `공연` 중심으로 통일하고 내부 `stage` 모델과 분리 | 기획 + 개발 |
| P0-3 | 멤버 반응 상태 모델 확정: 조회/하트/댓글/전원 반응 | 기획 + 개발 + 디자인 |
| P0-4 | 실제 시각 검토 화면과 단순 명세 화면을 분리 표기 | 디자인 + 기획 |
| P0-5 | 업로드 → 대기 → 멤버 반응 → 알림 → 자랑 카드 루프 완성 | 전원 |

## 2. 제품 원칙 — 유지할 것

### 2.1 핵심 감정

제품의 가장 중요한 보상은 팬 좋아요 수가 아니라 **멤버의 실제 반응**이다.

```text
팬의 순간
→ 콘텐츠 게시
→ 멤버에게 노출
→ 멤버의 조회/하트/댓글
→ 알림
→ 반응 상세 확인
→ 자랑 카드 공유
```

### 2.2 접근 정책

- 로그인 없이 공연·영상·명예의 전당·이벤트를 자유롭게 열람한다.
- 하트·댓글·업로드·월드컵 투표·마이페이지는 로그인 후 이용한다.
- 로그인 유도 후에는 원래 사용자의 의도로 복귀한다.
  - 하트 시도 → 로그인 → 해당 영상에서 하트 완료
  - 댓글 시도 → 로그인 → 해당 영상의 댓글 입력 상태 복귀
  - 투표 시도 → 로그인 → 해당 월드컵 대진 복귀
  - 업로드 시도 → 로그인 → 업로드 시트의 시작 단계 복귀

### 2.3 시각 원칙

- 페이지 배경은 `#F7F7FA`, 카드는 `#FFFFFF`를 기본으로 한다.
- 콘텐츠 썸네일이 시각적 색을 담당하고 UI는 차분하게 유지한다.
- 보라색은 행동·브랜드·멤버 반응에 제한적으로 사용한다.
- 네온, 글로우, 컨페티, 과도한 게임화는 사용하지 않는다.
- 큰 그림자보다 `1px border + shadow-sm`를 기본으로 한다.
- 모바일 390–430px을 우선 검증한다.

## 3. P0 결정사항 및 실행 요구사항

## P0-1. 브랜드 그라데이션 규칙 확정

### 현재 문제

문서에는 그라데이션을 `MOMENT 워드마크·＋올리기 버튼`에만 사용한다고 되어 있지만, 최신 HTML에서는 다음에도 사용된다.

- `CELEBUS` 워드마크
- 커버의 `CELEBUS`
- 태그라인의 `Their response.`
- 홈 히어로 전체 배경
- 모바일 홈 히어로

또한 문서의 `MOMENT 그라데이션`과 실제 HTML의 `CELEBUS 그라데이션`이 다르다.

### 권장 결정안

현재 브랜드 구조와 시각 결과를 고려해 다음을 권장한다.

```text
CELEBUS  = 브랜드 그라데이션
MOMENT   = 짙은 본문색
```

그라데이션 허용 범위:

1. `CELEBUS` 워드마크
2. `＋ 올리기` 버튼
3. 필요 시 브랜드 소개용 대형 로고

그라데이션 금지 범위:

- 일반 본문
- 태그라인 전체
- 멤버 반응 배지 전체
- 세그먼트·탭 활성 상태
- 영상 카드 배경
- 홈 히어로 배경
- 월드컵 카드 전체 배경

홈 히어로는 실제 영상 썸네일을 사용하고, 멤버 반응 배지만 올린다.

### 권장 토큰

```css
--brand-grad: linear-gradient(120deg, #A855E8, #6C4DE6);
--primary: #6C4DE6;
--primary-strong: #4E2FC0;
--primary-soft: #F1EBFF;
```

### 완료 기준

- [ ] 브랜드 문서·HTML·실제 앱에서 그라데이션 대상이 동일하다.
- [ ] `CELEBUS MOMENT` 락업에서 CELEBUS/MOMENT 처리 규칙이 고정된다.
- [ ] 태그라인의 강조 색상은 그라데이션이 아닌 단색으로 통일한다.
- [ ] 홈 히어로가 실제 썸네일 기반으로 보인다.
- [ ] 그라데이션 사용처가 디자인 토큰 문서에 명시된다.

## P0-2. 사용자 용어를 `공연` 중심으로 통일

### 원칙

내부 데이터 모델과 라우트에서 `stage`를 유지할 수 있다. 그러나 사용자 화면에서 무대·극장 은유를 다시 강화하지 않는다.

### 용어 매핑

| 내부/현재 | 사용자 UI 권장 |
|---|---|
| `stage` | 내부 데이터 모델로 유지 가능 |
| 스테이지 | 공연 |
| 스테이지 목록 | 공연 |
| 스테이지 상세 | 공연 영상 |
| 스테이지 선택 | 공연 선택 |
| 스테이지 레일 | 진행 중인 공연 |
| 스테이지명 · 전체 | 공연명 · 전체 |
| 무대에 올리기 | 영상 올리기 |
| 멤버에게 자랑하는 무대 | 멤버에게 보여줄 영상 |
| 스테이지 개설 | 공연 아카이브 개설(관리자용) |

### 하단 탭 권장안

```text
홈 · 공연 · ＋ · 이벤트 · 마이
```

### 안내 카피

공연 목록 상단:

> 공연별로 팬 영상을 모아보는 아카이브예요.

업로드 시트:

> 링크만 붙여넣으면 끝 · 멤버에게 보여줄 수 있어요

### 완료 기준

- [ ] 사용자 노출 카피에서 `스테이지`와 `무대`를 일괄 검토한다.
- [ ] 내부 `stage` 타입·테이블·라우트는 필요 시 유지하되 UI 번역 레이어를 둔다.
- [ ] 하단 탭 라벨을 `공연`으로 확정한다.
- [ ] HTML 리뷰 덱의 컨셉·화면 캡션·플로우도 동일한 용어로 갱신한다.
- [ ] 검색·분석·관리자 화면에서만 `stage`를 쓸지 범위를 문서화한다.

## P0-3. 멤버 반응 상태 모델 확정

### 반드시 구분할 상태

| 상태 | 의미 | 사용자 카피 예시 |
|---|---|---|
| 조회 | 멤버가 콘텐츠를 본 이벤트 | `주연 님이 회원님의 영상을 봤어요` |
| 하트 | 멤버 계정이 하트를 보냄 | `주연 님이 하트를 보냈어요` |
| 댓글 | 멤버 계정이 댓글을 남김 | `주연 님이 댓글을 남겼어요` |
| 복수 반응 | 여러 멤버가 반응 | `멤버 3명이 반응했어요` |
| 전원 반응 | 대상 멤버 전원이 반응 | `멤버 전원이 반응했어요` |

### 중요한 제품 결정

기획·개발은 먼저 다음 질문에 답해야 한다.

1. `봤어요`는 실제 조회 이벤트인가?
2. 조회 이벤트를 어떤 기준으로 인정하는가?
3. 멤버가 영상을 열었지만 재생하지 않은 경우도 조회로 볼 것인가?
4. 하트·댓글은 조회 없이 가능한가?
5. 멤버 전원 반응은 조회·하트·댓글 중 무엇을 기준으로 하는가?

권장 기본안:

- 조회: 멤버가 해당 영상 상세 또는 외부 임베드 영역에 진입한 기록
- 하트: 멤버 계정의 명시적 하트 행동
- 댓글: 멤버 계정의 명시적 댓글 행동
- 전원 반응: 정의된 반응 기준을 충족한 멤버 수가 전체 멤버 수와 같을 때만 표시
- 실제 데이터가 없으면 `멤버가 봤어요`를 생성하지 않음

### UI 규칙

- 팬 좋아요와 멤버 하트는 아이콘·텍스트·카운트 영역을 분리한다.
- 멤버 공식 계정 여부는 체크 표시로 분리한다.
- 검증 배지의 체크가 멤버 행동 자체를 대신하지 않게 한다.
- `멤버 전원 하트! 🏆`처럼 느낌표·트로피를 기본 상태에 사용하지 않는다.
- 권장 표현: `멤버 전원이 하트를 보냈어요` 또는 `멤버 전원 반응`.
- `그랜드슬램`은 내부 상태명 또는 특별 공유 카드 문구로 제한한다.

### 완료 기준

- [ ] 데이터 모델에 조회·하트·댓글 이벤트가 분리되어 있다.
- [ ] 카피 생성 규칙이 상태별로 정의되어 있다.
- [ ] 팬 좋아요와 멤버 하트가 시각적으로 분리되어 있다.
- [ ] 전원 반응 계산 조건이 문서화되어 있다.
- [ ] 멤버 반응이 없는 콘텐츠에 멤버 반응 라인이 노출되지 않는다.
- [ ] 알림 타입이 상태별로 분리된다.

## P0-4. 실제 시각 검토 범위와 명세 범위 분리

### 현재 확인된 실제 모바일 목업

- 홈
- 공연 상세(현재 덱에서는 스테이지 상세 표기)
- 영상 상세
- 월드컵

### 인벤토리에는 있으나 별도 시각 목업이 필요한 화면

- 공연 목록
- 올리기 시트
- 이벤트 전체
- 명예의 전당
- 마이페이지
- 알림
- 로그인 유도 모달
- Loading
- Empty
- Error
- NotFound
- 멤버 반응 대기

### 권장 상태 표기

| 표기 | 의미 |
|---|---|
| `Visual reviewed` | 실제 목업/캡처로 시각 검토 완료 |
| `Spec defined` | 구조·카피·동작만 정의됨 |
| `Needs state review` | 기본 화면은 있으나 상태 디자인 미검토 |

### 완료 기준

- [ ] 화면 인벤토리의 `✅ 라이트` 표기를 위 3단계로 교체한다.
- [ ] 최소한 올리기 시트·알림·마이·명예의 전당 목업을 추가한다.
- [ ] 로그인 모달과 멤버 반응 대기 상태를 추가한다.
- [ ] 각 화면의 주요 Empty/Error/NotFound 상태를 최소 1개씩 추가한다.
- [ ] 목업 캡션과 실제 표시 요소가 일치한다.

## P0-5. 핵심 사용자 루프 완성

### 권장 사용자 여정

```text
공연 발견
→ 다른 팬 영상 둘러보기
→ 영상 올리기
→ 로그인(필요 시)
→ 공연 선택
→ 링크 붙여넣기
→ 미리보기 확인
→ 카테고리 선택
→ 게시
→ 공개 완료
→ 멤버 반응 대기
→ 멤버 조회/하트/댓글
→ 알림 수신
→ 반응 상세 확인
→ 자랑 카드 공유
```

### 반드시 설계할 중간 상태

1. 게시 완료
2. 멤버 반응 대기 중
3. 멤버가 조회함
4. 멤버가 하트를 보냄
5. 멤버가 댓글을 남김
6. 멤버 전원이 반응함

### 완료 기준

- [ ] 게시 직후의 상태가 정의되어 있다.
- [ ] 반응 대기 중인 내 영상 목록이 있다.
- [ ] 멤버 반응 알림에서 영상 상세로 바로 이동한다.
- [ ] 알림 클릭 후 원래 영상과 반응 위치가 유지된다.
- [ ] 자랑 카드가 실제 멤버 반응 상태에 맞는 문구를 사용한다.
- [ ] 업로드 실패·임베드 실패·공연 마감 상태가 정의되어 있다.

## 4. 화면별 상세 액션

## 4.1 홈 `/`

### 유지

- 멤버 반응이 있는 대표 콘텐츠를 히어로로 노출
- 최근 멤버 반응 섹션
- 진행 중 공연
- 월드컵
- 명예의 전당
- 데이터가 없는 섹션은 자동 숨김

### 수정

- 히어로 배경은 그라데이션이 아닌 실제 영상 썸네일
- 썸네일 위에는 멤버 반응 배지와 재생 글리프만 제한적으로 배치
- 첫 방문 시 짧은 설명과 CTA를 함께 제공
- 홈 전체 스크롤 구조가 리뷰 덱에서 확인되도록 긴 모바일 목업 또는 상·중·하 3개 캡처 추가

### 권장 우선순위

1. 멤버 댓글이 있는 영상
2. 멤버 하트가 많은 영상
3. 멤버 전원이 반응한 영상
4. 팬 좋아요가 높은 영상

`인기 영상`보다 `멤버 반응이 확인된 영상`을 우선한다.

## 5. 카피 및 보이스 가이드

### 공식 보이스

- 따뜻하지만 과장하지 않는다.
- 멤버의 행동을 실제 행동으로 표현한다.
- 멤버 반응이 없을 때 반응을 암시하지 않는다.
- 보상감을 주되 게임 이벤트처럼 과장하지 않는다.

### 권장/비권장

| 비권장 | 권장 |
|---|---|
| 멤버들이 봐요 | 멤버에게 보여줄 수 있어요 |
| 멤버 전원 하트! 🏆 | 멤버 전원이 하트를 보냈어요 |
| 멤버에게 자랑하는 무대 | 멤버에게 보여줄 영상 |
| 무대에 올리기 | 영상 올리기 |
| 스테이지 | 공연 |
| 멤버 인기 영상 | 멤버 반응이 있는 영상 |

### 태그라인

브랜드 태그라인은 유지한다.

```text
Your moment. Their response.
```

제품 UI의 한국어 보조 카피는 상황에 따라 다음을 사용한다.

```text
내 순간에, 멤버가 답해요.
내가 남긴 순간에, 멤버가 답해요.
```

태그라인에 그라데이션을 적용하지 않고 단색으로 처리한다.

- 작은 텍스트에 `#A6A7B2` 사용 금지

- 긴 한국어 문장은 1.55–1.6 line-height 권장
- 화면 제목과 카드 제목의 weight 차이를 일관되게 유지

## 10. 최종 결론

새로운 시각 스타일을 찾는 것이 현재의 우선 과제는 아니다. 이미 정한 라이트·뉴트럴·CELEBUS 바이올렛 방향은 충분히 유효하다.

지금 필요한 것은 다음 원칙을 실제 제품에 정확히 맞추는 일이다.

1. **브랜드 규칙과 화면 구현을 일치시킨다.**
2. **사용자 언어에서 무대 은유를 제거하고 공연 아카이브로 명확히 한다.**
3. **멤버의 조회·하트·댓글을 신뢰할 수 있는 상태로 분리한다.**
4. **업로드 후 반응을 기다리고 확인하고 자랑하는 루프를 완성한다.**
5. **명세만 있는 화면과 실제 시각 검토가 끝난 화면을 구분한다.**

이 다섯 가지가 완료되면 CELEBUS MOMENT는 단순한 팬 영상 아카이브가 아니라, **팬의 순간이 멤버의 반응으로 돌아오는 경험을 중심으로 한 플랫폼**으로 명확해진다.
