# Phase 3 — 이벤트 재설계: 챌린지 중심 (구현 계획)

> 결정 반영: ① **월드컵 → 챌린지 중심으로 교체** ② **공식 채널 피처링 보상은 소속사(ix) 확인 필요** → 설계에서 확정 보상으로 명시하지 않고 "가능성"으로만 다룸.
> 성격: 스키마 + BO + 앱 + 마이그레이션. **마이그레이션은 dev 선검증 → 프로드**(메모리 룰).
> 아래는 착수 전 확정용 계획 — 승인 후 구현.

---

## 1. 컨셉

**챌린지** = 관리자가 여는 주제형 이벤트. "이번 주 직캠 챌린지" 처럼 테마·기간을 걸고, 팬이 영상을 제출 → 팬·멤버가 반응 → 기간 종료 시 상위 인정.

코어 루프 강화: **테마가 빈 캔버스를 열고(콜드스타트 완화) → 제출이 모이고 → 멤버가 반응(핵심) → 상위가 인정받는다.**

---

## 2. 데이터 모델 (안)

기존: `stages`(공연 아카이브) · `stage_events`(월드컵) · `stage_posts` · `member_hearts` · `worldcup_runs`.

### 방안 A (권장): stage_events에 유형 추가
- `stage_events.type`: `'worldcup' | 'challenge'` (신규 컬럼, 기본 'challenge')
- 챌린지 설정 컬럼: `theme_title`(3언어), `submit_start_at`·`submit_end_at`, `rank_by`(`member_hearts | fan_likes | combined`), `reward_note`(3언어, 피처링은 '가능성'으로만)
- 제출: 챌린지는 특정 `stage_id`에 연결 → 그 공연에 기간 내 올라온 `stage_posts`가 자동 엔트리. (별도 제출 테이블 불필요, 기존 업로드 재사용)
- 결과: 기간 종료 후 `rank_by` 기준 집계(뷰). 월드컵의 `worldcup_runs`·`worldcup_stats`는 challenge에서 미사용.

> 방안 A는 기존 업로드/스테이지 자산을 최대 재사용. worldcup과 스키마 공존(전환기).

### 방안 B: 별도 challenges 테이블 (신설)
- 더 깔끔하나 신규 테이블·RLS·뷰·RPC 전부 신설 → 공수 큼. 파일럿엔 과함.

→ **방안 A 채택 권장.**

---

## 3. BO (관리자)
- 이벤트 생성 화면에 **유형 선택(월드컵/챌린지)** 추가
- 챌린지 폼: 테마 타이틀(3언어)·대상 공연·기간·랭킹 기준·보상 안내(피처링은 '가능성' 문구)
- 결과 화면: 기간 종료 후 상위 N 자동 집계 노출(수동 선정 옵션)

## 4. 앱
- `/events`: 월드컵 카드 → **챌린지 카드**로 대체(진행중/마감/결과). 기존 월드컵은 전환기 병행 노출 후 정리
- 챌린지 상세: 테마·기간·**바로 제출 CTA**(업로드 플로우 재사용) · 엔트리 목록(몰입 피드 진입) · 실시간 리더보드(멤버 하트/좋아요)
- 결과: 상위 인정(명예의 전당 연계) + 보상 안내(응모권/덕력 등 확정분 + 피처링 '가능성')

## 5. 보상 처리 (소속사 확인 완료 — 확정)
- **SNS 피처링(확정)**: 우수작은 **CELEBUS 공식 SNS에 게시** → **RT** 또는 **공동작업자(collaborator) 승인 후 재게시**. (원작자 크레딧·동의 전제 — 업로드 약관의 공식 활용 동의와 정합)
- **실물/디지털 보상(확정, 현 시점 제공 가능)**: **콘서트 티켓 · 실물 굿즈 · 디지털 굿즈**
- **후속 연동 예정**: 응모권 · 덕력(메인앱 연동 시 추가). 현 파일럿에선 미노출/미약속
- 보상 안내는 실제 제공 가능한 것만 명시(허위 약속 금지)

## 5-1. 랭킹 기준 (확정) — 3신호 결합
- **멤버 하트 + 팬 하트(좋아요) + 조회수**를 골고루 결합해 순위 산정
- 결합식(초안): `점수 = w1·멤버하트 + w2·팬하트 + w3·조회수` (w는 BO 튜너블, 기본은 멤버하트 비중을 팬하트·조회수보다 다소 높게 — 코어 "멤버가 봐준다" 유지하되 3신호 골고루 반영)
- 정규화: 조회수는 스케일이 크므로 로그/상한 정규화로 하트류와 균형

### ⚠️ view(조회수) 추적 신설 — 이전 "view 미도입" 결정 번복 (확정)
- **어뷰징 방지 중심**으로 도입 + **조회수 UI 노출**(확정)
- 스키마: `stage_post_views`(post_id, 신원/세션 해시, 시각) — 신원·세션당 시간창(예: 30분) 내 1회만 유효 집계, `stage_posts.view_count`는 집계 뷰/컬럼로 노출
- 어뷰징 방지: SECURITY DEFINER RPC로만 집계(신원 쿠키 기준 dedup 창 + 서버 시각), 클라 임의 증가 불가. 몰입 피드 활성 시 1회 호출
- UI: 카드·상세·리더보드에 조회수 표기(하트류와 구분되는 중립 톤)

## 6. 월드컵 처리
- 즉시 삭제 대신 **전환기 병행 → deprecate**. 기존 dev 월드컵 데이터·라우트는 유지하되 신규 생성은 챌린지로 유도
- worldcup 관련 컴포넌트(EventPlay·WorldcupStandings)는 챌린지 전환 완료 후 정리

## 7. 마이그레이션 절차 (강제)
1. dev(`celeb-match-dev`)에 스키마 변경 적용·검증 (`scripts/db-apply-dev.sh`)
2. dev 앱·BO 실측 통과
3. 프로드(`CELEBUS-Feedback`) push
4. 각 단계 사용자 컨펌

## 8. 단계 분해 (착수 시)
1. 스키마: `stage_events.type` + 챌린지 컬럼 + 집계 뷰 (dev)
2. BO: 이벤트 생성/결과에 챌린지 지원
3. 앱: /events 챌린지 카드 + 상세(제출·리더보드) + 결과
4. 보상 문구(확정/가능성 분리) + 월드컵 전환 처리
5. dev 실측 → 프로드
