## 1. 개편 컨셉

**"팬이 소장한 영상(직캠·커버·편집)을 멤버들 보라고 올리는 상시 무대. 멤버의 하트가 훈장이 되고, 이벤트 기간엔 토너먼트 축제가 열린다."**

- 현재 FanStage는 "운영자가 여는 콘테스트에 기간 내 응모하는 앱" — 응모 마감이 지나면 죽는 공간이고, 팬끼리 좋아요를 주고받는 것 이상의 재미가 없다.
- 개편의 본질은 **무대의 방향 전환**: 아티스트가 주인공이고 팬이 관객인 구조를 뒤집어, **팬이 무대에 올리고 아티스트가 관객석에서 반응**하는 공간으로 만든다.
- 재미의 원천은 상(賞)이 아니라 **"멤버가 내 영상을 봤다"는 순간**이다. 보상 이벤트는 그 위에 주기적으로 얹히는 축제일 뿐이다.

### 감정 루프 (설계의 중심)
```
영상 업로드(상시) → 멤버 하트/열람 표시 ← ★ 도파민의 원천
      ↑                    │
      │            자랑 공유(SNS 바이럴)
      └── 계속 올릴 이유 ←──┘
              +
이벤트 기간: 누적+신규 영상 토너먼트 → 팬인기상·아티스트인기상·최다업로드상
```

### K-pop 팬덤 검증 근거
- "아이돌이 내 게시물에 좋아요 → 캡처해서 평생 자랑"은 이미 존재하는 팬덤 문화 — 본 개편은 그 순간을 제품화한다.
- 멤버 반응의 실현 가능성 확보: ix 미팅에서 영상 콘텐츠 협조 의향 확인, 게임에서 멤버(조주연)가 실제 SSO 계정으로 활동 중.

## 3. 핵심 시스템

### 3.1 상시 스테이지 (v1.2 구조 확정 — 공연 단위 컨테이너)
- **스테이지 = 관리자가 생성하는 공연 단위 컨테이너** (예: "2026 여름 부산 버스킹"). 유저는 해당 공연 스테이지에 영상을 올린다 → **공연별 영상 아카이브**가 핵심 구조.
- 스테이지는 기간 마감 없이 **상시(진행중)** — 관리자가 **보관** 전환 시 업로드 중단·열람만 가능(아카이브 보존). 숨김(비공개 준비) 지원.
- 홈 = 스테이지 목록(공연 카드) → 스테이지 진입 = 그 공연의 영상 피드 + 업로드.
- 게시물 유형 태그: 직캠 / 커버 / 편집 / 기타 — 스테이지 안의 보조 필터.
- **링크 임베드 방식 유지** (YouTube·TikTok·X·IG·Threads) — 기존 임베드 인프라 그대로. 직접 호스팅은 계속 제외: 스토리지·트랜스코딩 비용과 **저작권 책임 방어**(호스팅 플랫폼에 권리 처리 위임) 양면에서 임베드가 정답.
- 피드 정렬: 최신순 기본 + "멤버 하트" 필터(명예의 전당) + 카테고리 필터.
- 모더레이션: 기존 신고·숨김·검증 체계 유지.

### 3.2 멤버 하트 시스템 (개편의 심장)
인스타그램 문법 그대로 — 설명이 필요 없는 UI.

| 요소 | 설계 |
|------|------|
| 카드 표시 | 멤버가 하트 → **멤버 프로필 서클이 게시글에 영구 표시** (피드 썸네일에도 미니 아바타+💜) |
| 복수 하트 | 인스타식 **아바타 스택** + "주연 님 외 2명의 멤버가 좋아합니다" |
| 그랜드슬램 | 멤버 5인 전원 하트 시 특별 연출(카드 테두리·전용 뱃지) — 최상위 수집 목표 |
| 알림 | "주연 님이 회원님의 영상에 하트를 남겼어요 💜" — 인앱 우선, 웹푸시는 2차(§9) |
| 자랑 카드 | "멤버가 하트한 내 영상" 공유 이미지 생성(기존 공유카드 인프라) → SNS 바이럴 루프 |
| 신뢰 원칙 | 멤버 하트는 **is_member SSO 계정의 실제 액션만** 인정. 운영자 대행 입력은 두지 않는다(대행이 들통나는 순간 기능 전체의 신뢰 붕괴) |
| 운영 안전장치 | 하트 취소 허용(취소 시 표시 제거), 관리자에서 멤버 하트 이력 조회 |

- 멤버 식별·프로필: **game-app 멤버 시스템 재사용** — is_member 지정, 표시 이름 3언어, 프로필 이미지 우선순위(CELEBUS 프로필 > 관리자 업로드).

### 3.3 토너먼트 이벤트 — 이상형월드컵 형식 (확정)
레퍼런스: 이상형월드컵(PIKU 등)·뮤직월드컵. 이 장르의 핵심은 **"투표자 한 명 한 명이 자기만의 토너먼트를 플레이"**한다는 것 — 집계에 하트 하나 누르는 게 아니라, 두 영상 중 하나를 계속 고르며 **나만의 우승작**을 뽑는 게임이다. 투표 행위 자체가 재미가 되고, 결과("내 우승은 이 영상")가 공유 콘텐츠가 된다.

**진행 방식**
1. 이벤트 참가작 풀에서 투표자마다 **무작위 대진표 생성** (규모: 참가작 수에 맞춰 8강/16강/32강… 자동, 초과 시 무작위 샘플링·부전승 처리)
2. **1:1 대결 카드**(두 영상 나란히, 탭해서 선택) → 라운드 진행 → **나의 우승작 결정**
3. 결과 화면: "내 우승작" + 자랑 공유 카드 + 전체 랭킹 보기
4. 1인 다회 플레이 허용(대진이 매번 다름 — 재participation이 곧 재미), 단 **집계 반영은 계정당 N회 캡**(어뷰징 방지, SSO 계정 기반)

**집계 (팬인기상 산정 — 장르 표준 지표)**
- 1순위 **우승 비율**(개인 토너먼트 우승 횟수 ÷ 대진 등장 기회) · 2순위 **1:1 승률** — 무작위 대진이라 노출 기회가 통계적으로 공평해짐 (기존 "먼저 올린 영상이 유리한" 좋아요 집계의 구조적 불공정을 해소)
- 랭킹 페이지: 우승 비율·승률 실시간 공개(PIKU 문법)

**대상·참여**
- 대상 = 이벤트 이전 누적 업로드 + 기간 내 신규 (참가 신청 탭 한 번으로 기존 영상 출전 — 소급 포함이 "그동안 올린 보람"을 만든다)
- 참가작이 적어도 성립(8강부터 가능) — 규모 자동 적응이 월드컵 형식의 부수 장점
- **팬 투표 / 아티스트 투표 분리**: 팬 = 월드컵 플레이 집계, 아티스트 = 멤버 계정의 별도 픽(비공개 진행, 발표 시 공개)

### 3.4 보상 3종
| 상 | 기준 | 설계 노트 |
|----|------|-----------|
| 팬인기상 | 월드컵 집계 — 우승 비율(1순위)·1:1 승률(2순위) | 기존 인기상 확정(finalize) 인프라 확장 |
| 아티스트인기상 | 멤버 투표 결과 | 최고 영예 포지션. 멤버별 픽 공개 여부는 ix 협의 |
| 최다업로드상 | ⚠️ 단순 개수 금지 — **"유효 업로드 일수"**(신고·숨김 제외, 1일 최대 1건 인정) | 단순 개수 기준은 저질 대량 업로드를 유도하는 역인센티브. "꾸준히 올린 팬"을 상 주는 지표로 설계 |

- 클레임(배송·PII 파기) 흐름은 기존 것 유지 — 이미 견고함(감사 A-).

### 3.5 CELEBUS SSO 연동 — **최종 단계(W4, 운영 릴리즈 직전) 진행**

**신원 정책 (확정 — v1.3 개정)**
1. **열람은 로그인 없이 자유, 상호작용은 로그인 필수** — 스테이지·영상·명예의 전당·이벤트 **열람은 비로그인 공개**(공유·유입 루프 유지). 반면 **하트·댓글·업로드·월드컵 투표·마이페이지 등 모든 상호작용**은 CELEBUS 로그인이 있어야 하며, 미로그인 상태로 시도하면 **로그인 유도 모달**이 뜬다(전면 게이트 아님). 서버 쓰기 엔드포인트는 전부 로그인 검증(미로그인 401).
2. **익명 신원은 개발 기간(W1~W3)의 테스트 수단일 뿐** — dev 환경에서만 사용, 운영에 절대 노출되지 않는다. 운영에서 신원 쿠키는 오직 CELEBUS SSO 로그인으로만 발급된다(자동 익명 발급 폐지).
3. **W4 SSO 연동 시점에 전체 데이터 초기화** — 개발 기간의 익명 기반 데이터 + 기존 시즌1 데이터(보존 불필요 확인됨)를 전부 리셋하고 SSO 계정 기반으로 클린 스타트(게임 SSO 전환과 동일한 절차). 익명→SSO 데이터 이관이 없어져 전환 리스크가 크게 준다.

> **읽기 공개 결정(v1.3)**: 공유 링크로 들어온 사람이 로그인 없이도 영상과 무대를 볼 수 있어야 자랑·유입 루프가 산다. 따라서 공개 뷰(anon 읽기)는 **의도된 설계**이며, 로그인 장벽은 "행동하는 순간"에만 세운다.

- game-app 검증 패턴 이식: 클라이언트가 CELEBUS 계정 API를 직접 호출(쿠키 인증) → 서버 HMAC 신원 발급.
- 개발 기간에는 익명 신원으로 전 기능을 구축하고, W4에서 신원만 전환한다(§10 신원 추상화 원칙).
- 효과: ① 수기 닉네임·전화 입력 제거(**PII 수집 축소** — 전화는 수상 클레임 시에만) ② 업로드·투표·댓글·신고가 전부 계정 기반 → 어뷰징 근본 개선 ③ `linked_user_id` 예약 컬럼 실사용 ④ 게임과 동일 계정 = 허브 시너지.

### 3.6 댓글 시스템 (v1.1 추가)
영상 아래 팬들의 응원 댓글 — 하트가 "반응"이라면 댓글은 "대화"다. 단, **자유 텍스트 = 모더레이션 표면**이므로 다음 원칙으로 리스크를 통제한다.

| 항목 | 설계 |
|------|------|
| 작성 자격 | **SSO 로그인 필수** (익명 댓글 없음 — 계정 기반이 최대의 자정 장치) |
| 형식 | 텍스트 단문(200자) + 이모지. 대댓글은 1단만(스레드 무한 중첩 금지) |
| **멤버 댓글** | 멤버 계정 댓글은 **하이라이트 표시 + 최상단 고정** — 하트보다 강한 도파민. 멤버 발언 리스크는 ix와 가이드 합의(안전 톤) 후 활성화 |
| 모더레이션 | 금칙어 필터(게임앱 금칙어 체계 재사용) + 신고 → 자동 숨김 임계 + 관리자 큐. 업로더는 자기 게시물 댓글 숨김 가능 |
| 알림 | 내 영상에 댓글 → 인앱 알림 (멤버 댓글은 별도 강조 알림) |
| 제외 | 댓글 좋아요·랭킹 없음(댓글 경쟁 구도 방지), DM 없음 |

## 4. 화면 구조 개편

```
홈 = 스테이지 피드 (최신 업로드 + 멤버 하트 하이라이트)
├── 이벤트 탭: 진행 중 토너먼트(대결 카드·브래킷 현황) / 지난 이벤트 결과
├── 명예의 전당: 멤버 하트 영상 모음 + 역대 수상작
├── 업로드(+): 링크 붙여넣기 → 미리보기 → 카테고리 → 완료 (SSO 로그인 게이트)
└── 마이: 내 영상·받은 하트·수상 이력
```
- 현재 "콘테스트 목록이 홈" 구조에서 "피드가 홈, 이벤트는 탭" 구조로 — 상시 서비스의 정보 구조.

## 5. 데이터 모델 전환 (요지)

- `contest_entries`(콘테스트 종속) → **`stage_posts`(스테이지 소속)** 로 중심 이동 + 이벤트 참가는 연결 테이블(`event_entries`)로 분리 — 하나의 영상이 여러 이벤트에 출전 가능.
- 멤버 하트: `member_hearts`(post_id, member_user_id) — is_member 검증은 서버.
- **전환 경로**: 기존 시즌1 데이터는 스테이지 포스트로 흡수(콘테스트=첫 이벤트로 재해석). 파괴 변경 없이 additive 마이그레이션 + 뷰 전환.
- **개발/운영 분리 (v1.1 확정)**: contest-app도 game-app과 동일하게 분리 운영한다 —
  - 로컬 개발 = **dev 프로젝트(celeb-match-dev)** 사용 (contest_* 스키마는 프로드 덤프로 이미 dev에 존재)
  - 모든 SQL은 dev 선적용·검증 후 프로드 반영 (`scripts/db-apply-dev.sh` 도입 — contest-app은 번호 SQL 파일 방식이므로 파일 단위 적용 스크립트)
  - 프로드 배포는 Vercel 환경변수(프로드 키) — 로컬 전환과 무관

## 10. 마일스톤

**SSO 연동은 마지막 단계(운영 릴리즈 직전)로 확정** — 개발 기간엔 기존 익명 신원(HMAC 쿠키)으로 전 기능을 구축·검증하고, 최종 단계에서 신원만 SSO로 전환한다. 이를 위해 W1부터 **신원 추상화 원칙**을 지킨다: 모든 신규 기능(하트·댓글·월드컵 집계)은 "사용자 식별자" 인터페이스에만 의존하게 구현 — 지금은 익명 ID, 마지막에 SSO 계정 ID로 갈아끼우는 구조(004의 `linked_user_id`가 그 자리).

| 단계 | 산출물 | 게이트 |
|------|--------|--------|
| W0 설계 확정 | 데이터 모델 전환 설계 + ~~개발/운영 분리~~(✅ 완료) + ix 실무 조율(하트 리듬·댓글 가이드) | 사용자 승인 (멤버 참여는 기확정) |
| W1 스테이지 전환 | 상시 업로드 피드(dev에서 테스트 데이터로 개발 — 시즌1 이관 불필요, W4에서 전체 초기화 예정) + 신원 추상화 레이어 | 업로드 E2E |
| W2 멤버 하트·댓글 | 하트 시스템 전체(카드 표시·스택·알림·자랑 카드·명예의 전당) + 댓글(§3.6) + 멤버 전용 UI — dev에서 테스트 멤버 계정으로 검증 | 하트·댓글 E2E 리허설 |
| W3 월드컵 이벤트 | 개인 대진 월드컵(대결 카드·나의 우승작·집계 랭킹)·아티스트 투표·3종 시상 + 운영 도구 정비(§8) | 집계 공정성 시뮬레이션(노출 균등) |
| **W4 SSO + 초기화 + 운영 릴리즈** | **CELEBUS SSO 연동(게임 패턴)** → 전면 로그인 게이트 적용 → **전체 데이터 초기화**(익명 기간 + 시즌1) → 실제 멤버 계정 지정 → 멤버 하트 라이브 리허설 → 프로드 배포 | SSO 전 기능 회귀 검증 · 익명 진입 경로 0건 확인 · 멤버 실계정 하트 확인 · 베타 이벤트 1회 |
