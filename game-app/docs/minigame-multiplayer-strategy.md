# CELEB 미니게임 — 공통 멀티플레이 전략

| 항목 | 내용 |
|------|------|
| 문서 버전 | v1.0 |

| 참조 방식 | 각 게임 기획서의 멀티 섹션은 본 문서를 공통 전제로 한다 |

## 1. 배경 — 무엇이 문제이고, 무엇이 문제가 아닌가

- 실측(관리자 대시보드, 2026-07): 일 방문 ~63명 · 일 활성 ~41명 → **임의 시점 동시접속은 한 자릿수**로 추정.
- 이 규모에서 성립하지 않는 것은 딱 두 가지다:
  1. **상시 랜덤 매칭** — 모르는 사람이 같은 순간 대기열에 있어야 하므로 빈 로비 확정. 빈 매칭 화면은 "죽은 게임" 인상을 주는 최악의 UX.
  2. **충돌·상호작용 있는 고빈도 실시간 동기화**(밀치기·아이템 명중 판정) — 전용 게임서버·넷코드 프로젝트 규모.
- 이 두 가지를 **구조적으로 회피**하면, 현재 유저 풀과 현재 인프라로 멀티플레이가 성립한다. 아래 3원칙이 그 방법이다.

## 2. 멀티플레이 3원칙

### 원칙 ① 초대 링크 프라이빗 룸 — 매칭 풀 문제를 구조로 회피
- 랜덤 매칭은 상대가 "동시에 있어야" 하지만, 초대 룸은 **유저가 상대를 데려온다**. skribbl.io·Gartic Phone이 매칭 시스템 없이 링크 하나로 성립하는 검증된 구조.
- 팬덤은 오픈채팅·커뮤니티로 **이미 조직된 집단** — "링크 공유해서 같이 하자"가 일반 캐주얼 유저 대비 훨씬 잘 작동하고, 링크가 외부 커뮤니티에 돌면 **신규 유입 통로**가 된다.

### 원칙 ② 정기 이벤트 타임 — 동접 부족을 팬덤 문화로 회피
- 얇게 퍼진 유저를 **약속된 시간에 집결**시키면 그 순간만큼은 동접이 성립한다(HQ Trivia 모델). 예: "금요일 밤 9시 스케치 타임", 주말 러시 토너먼트.
- 팬덤은 총공·스밍 등 **정시 집결 문화가 체화된 유저층** — 이 모델과 시너지가 가장 크다. CELEBUS의 Survival Trivia가 이미 "정시 시작·10분 전 입장" 구조로 같은 DNA를 갖고 있다.

### 원칙 ③ 충돌 없는 실시간 — 넷코드 난이도를 게임 룰로 회피
- 실시간 멀티의 진짜 비용은 충돌·상호작용 **판정**이다. 이를 룰에서 제거하면(트랙마니아의 무충돌 멀티 레이싱 모델) 위치·상태를 저빈도로 공유만 하면 되고, 지연이 승패 판정에 영향을 주지 않는다.

## 3. 게임별 적용 매트릭스

| 게임 | 런칭(1차) | 2차 | 운영 이벤트 | 비고 |
|------|-----------|-----|-------------|------|
| **CELEB 스케치** | 비동기 그리기·맞히기 + **파티룸(초대 3~8인)** | 게스트(비로그인) 파티 참여 확대 | 정기 스케치 타임(주 1회) | **허브 멀티 파일럿 1순위** — 기술 난이도 최저(스트로크 중계 = 화이트보드 수준) |
| **CELEB 마블** | 멤버 AI 3인전 | **프라이빗 룸 2~4인 턴제** | 정기 마블 토너먼트 | 턴제 저빈도 동기화. 공수의 절반은 이탈·AFK 처리(§5) |
| **CELEB 러시** | 타임어택 + 내 고스트 | **라이브 고스트**(동시 출발·무충돌) + 상위 랭커 고스트 | 주말 토너먼트 타임 | 충돌·아이템 상호작용형 실시간은 계속 제외 |
| **CELEB 아지트** | 비동기(방 방문 + 스티커 반응) | 방문 확대(하트·스티커) | 시즌 전시 이벤트 | **의도적 비동기 유지** — 장르 특성상 동시 존재가 재미에 기여하지 않음 |

- 도입 순서: **스케치 파티룸(파일럿) → 마블 프라이빗 룸 → 러시 라이브 고스트.** 파일럿에서 실시간 인프라·이탈 처리 표준을 검증한 뒤 확산한다.

## 4. 기술 기반 (추가 서버 불필요)

- **Supabase Realtime**(현 인프라에 포함): 채널 브로드캐스트 + 프레즌스(입장·이탈 감지)로 다음을 감당한다 —
  - 스케치: 스트로크 중계 + 정답자 알림 (이벤트 빈도 낮음)
  - 마블: 턴 상태 동기화 (턴당 수 회)
  - 러시: 위치 브로드캐스트 저빈도(10Hz 내외) + 클라 보간 — 무충돌이라 지연이 판정에 영향 없음
- 전용 게임서버가 필요한 것은 "충돌 있는 고빈도 물리 동기화"뿐이며, 본 전략은 이를 전부 회피한다.
- 방 상태의 권위: 결과 확정(점수·보상)은 항상 서버 검증 경유 — 실시간 채널은 중계만 담당하고 정산의 권위가 되지 않는다.

## 5. 공통 설계 표준 (모든 멀티 모드가 따를 것)

| 항목 | 표준 |
|------|------|
| 이탈·AFK | 턴제: 턴 타이머(30초) 초과 시 자동 행동 → 2회 연속 시 AI 대체. 실시간: 라운드 스킵 처리. 복귀 시 재입장 허용(방 유지 시간 내) |
| 재접속 | 새로고침·백그라운드 복귀 시 방 상태 재동기화로 복귀 (모바일 웹 필수 — 홈버튼·전화 수신이 일상) |
| 방 수명 | 인원 미달·전원 이탈 시 자동 해산. 좀비 방 방지 |
| **랭킹 반영 금지** | 프라이빗 룸 성적은 주간 경쟁 랭킹에 **미반영** — 초대 룸은 담합(짜고 치기)이 가능하므로 경쟁 보상과 절연한다. 재미·소셜 전용. 미션("친구와 1판")은 허용 |
| 이벤트 타임 랭킹 | 정기 이벤트만 별도 이벤트 랭킹·보상 운영(전원 동일 조건이므로 공정 성립) |
| 게스트 참여 | 링크로 열람·체험까지 허용, 참여·보상은 로그인 필수(어뷰즈 차단 + 가입 전환 루프) |

## 6. 랜덤 매칭 개방 조건 (지표 게이트)

상시 랜덤 매칭은 아래 지표 충족 시에만 단계 개방한다. 조건 미달 상태의 개방은 금지(빈 로비 노출 방지).

| 단계 | 조건(예시 — 운영 데이터로 보정) | 개방 |
|------|--------------------------------|------|
| 1 | 피크 시간대 동접 50+ 이 1주 지속 | 피크 시간대 한정 랜덤 매칭 |
| 2 | 전일 시간대 동접 100+ | 상시 랜덤 매칭 |
| — | 미달 | 초대 룸·이벤트 타임만 유지 |

## 7. 운영 이벤트 타임 — 실행 가이드

- 주기: 주 1회 고정 요일·시각부터 시작(예: 금 21:00 KST). 홈 허브·아지트에 카운트다운 배너.
- 구성: 30~60분 윈도우 내 참여형(스케치: 공통 제시어 라운드 / 러시: 지정 트랙 기록전 / 마블: 토너먼트 브래킷).
- 보상: 이벤트 랭킹 한정 보상(기존 CP 스케일). 참가만 해도 소액(집결 자체가 목적).
- 지표: 이벤트 시간대 동접이 §6 게이트의 실측 근거가 된다 — 이벤트는 재미이자 **랜덤 매칭 개방 가능성을 측정하는 실험**이다.
