## 1. 컨셉

**"V01D 멤버 카트를 몰고 60~90초 트랙을 달려 최고 기록에 도전하는 세로형 캐주얼 레이싱."**

- 카트라이더 초기의 **아기자기한 카툰 카트 + 드리프트 손맛**을 목표 감성으로 한다.
- 실시간 대전이 아니라 **기록 경쟁(타임어택) + 고스트(내 최고 기록·상위 랭커의 주행 재생) 대전**이 코어. 팬덤 게임의 경쟁 구도("멤버/다른 팬의 기록을 이겨라")와 CELEB MATCH의 랭킹 문화를 그대로 잇는다.
- 5인 멤버(유찬·주연·케빈·지섭·노스케)가 각자 악기 모티프 카트를 탄다. 성능 차등은 없고 **외형+전용 부스터 이펙트만 차등**(밸런스 민원 원천 차단, 최애 선택은 순수 애정 표현).

### 왜 이 게임인가 (포지셔닝)
- CELEB MATCH(퍼즐)가 "두뇌·수집" 축이라면, 레이싱은 **"반사신경·속도감"** 축 — 유저 풀이 겹치지 않고 확장된다.
- 주행 기록은 초 단위 숫자라 **랭킹·공유(기록 인증 카드)와 궁합이 가장 좋은 장르**다.

## 2. 확정 전제 (리서치 근거)

기획 방향을 좌우하는 웹/PWA 제약을 사전 검증했다. 아래는 추측이 아니라 확인된 사실이다.

| # | 확인된 제약 | 기획 반영 |
|---|------------|-----------|
| 1 | **iOS Safari/PWA는 화면 방향 잠금·전체화면 불가** ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock), [iOS PWA 가이드](https://gist.github.com/fozzedout/5e77925381991a9570151550992baf14)) | **세로형(포트레이트) 레이싱으로 설계**. 가로 강제 불가능. 마리오카트 투어가 세로형 카트 UX를 대규모로 검증했음 |
| 2 | **자이로(틸트) 조작은 iOS 13+에서 사용자 탭으로 권한 요청 필수** ([구현 가이드](https://leemartin.dev/how-to-request-device-motion-and-orientation-permission-in-ios-13-74fc9d6cd140), [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Device_orientation_events)) | 기본 조작은 **터치(좌우 스티어 + 드리프트 버튼)**. 틸트는 설정에서 켜는 옵션(권한 요청 UX 포함) |
| 3 | **three.js 로우폴리 레이싱은 모바일 웹에서 상용 수준 검증됨** ([PolyTrack](https://polytrack.art/), [카트 데모(오픈소스)](https://github.com/cconsta1/threejs_car_demo)) | 렌더링은 로우폴리 3D 채택 가능. 단 §8의 성능 예산 준수 |
| 4 | 오디오는 사용자 제스처 후 언락 필요 (CELEB MATCH에서 이미 해결한 패턴 보유) | 기존 오디오 언락·BGM 파이프라인 재사용 |

## 3. 코어 루프

```
[홈 허브] → 트랙 선택 → (멤버/카트 확인) → 카운트다운 3·2·1
   → 주행 60~90초 (스티어·드리프트·부스터)
   → 완주 → 기록 확정 → 랭킹 반영 + 신기록 연출
   → 보상(미션 진행) → 재도전(고스트와 대결) or 홈
```

- **1판 = 60~90초**: CELEB MATCH와 동일한 "출퇴근 한 판" 호흡.
- 재도전 동기 = **자기 고스트 추월**. 신기록 갱신 시 고스트가 즉시 갱신되어 "방금의 나"와 계속 싸우게 된다 (검증된 리텐션 루프 — 트랙마니아·PolyTrack 계열의 코어).

## 4. 조작 (세로형 기준)

| 조작 | 방식 | 비고 |
|------|------|------|
| 가속 | **자동** (오토 액셀) | 세로형·캐주얼 표준. 마리오카트 투어와 동일 판단 |
| 스티어 | 화면 좌/우 하단 터치 홀드 (또는 드래그 스티어) | 한 손 조작 가능해야 함 |
| 드리프트 | 스티어 중 반대 엄지로 드리프트 버튼 홀드 → 게이지 충전 | 카트라이더 감성의 핵심. 충전 단계 1·2단 색 변화 |
| 부스터 | 드리프트 게이지 만충 시 자동 발동 (또는 탭 발동 옵션) | 발동 시 화면 연출 + 멤버별 전용 이펙트 |
| 틸트(옵션) | 설정에서 활성화, iOS는 권한 요청 탭 필요 | 기본 꺼짐 |

- **아이템전은 런칭 범위에서 제외**한다. 아이템전은 실시간 상호작용이 있어야 재미가 성립하는데(맞히는 대상 필요) 고스트 대전과 상성이 나쁘다. 스피드전(드리프트·주행선)에 집중.

## 6. 콘텐츠 볼륨 (런칭 최소)

| 항목 | 수량 | 내용 |
|------|------|------|
| 트랙 | **3개** | ① 스타디움(무대·튜토리얼 겸용, 쉬움) ② 네온 시티(도심 야경, 중간) ③ 코스믹 하이웨이(우주, 어려움·지름길 1개) |
| 캐릭터 | 5명 | V01D 멤버 전원. 성능 동일, 외형·부스터 이펙트만 차등 |
| 카트 | 멤버당 1대 (기본) | 악기 모티프(드럼 카트·기타 카트 등). 추가 카트는 스킨 시스템(기보류 설계)과 통합해 2차 |
| BGM | 트랙당 1곡 | V01D 실곡 재사용 (기존 4곡 보유) |

- 트랙은 "폭 넓게, 벽 부드럽게, 실패해도 완주 가능"이 원칙. 낙사·리타이어 없음(캐주얼 팬 타깃 — 좌절 요소 최소화).
- 트랙 3개가 적어 보이지만, **고스트 경쟁 구조에서는 트랙 수보다 기록 갱신 루프가 콘텐츠**다. 얕고 넓게 5~6개를 만드는 것보다 3개를 깊게 다듬는 것이 초기 품질에 유리하다.

## 7. 경제·보상 (기존 CP 경제에 통합)

**원칙: 기존 CELEB MATCH 경제 붕괴 금지.** 판당 무제한 CP 지급은 인플레를 유발하므로 기존과 동일하게 **미션·주간 랭킹 보상 중심**으로 설계한다.

| 보상 경로 | 내용 |
|-----------|------|
| 데일리 미션 풀에 레이싱 미션 추가 | 예: "오늘 레이싱 2판", "부스터 5회 발동", "신기록 갱신" (기존 미션 로테이션에 편입) |
| 주간 랭킹 보상 | 트랙별 주간 TOP10에 기존과 동일 스케일의 CP (기존 보상표 재사용) |
| 완주 보상 | 첫 완주 시에만 소액 (트랙당 1회) |

- 소비처: 기존 상점(하트·아이템)과 공유. 레이싱 전용 소비처(카트 스킨)는 스킨 시스템과 함께 2차.

## 8. 기술 검토

### 렌더링 방식 비교 (핵심 의사결정)

| 방식 | 장점 | 단점 | 판정 |
|------|------|------|------|
| A. 로우폴리 3D (three.js) | 카트라이더 감성 재현도 최고, 검증 사례 다수(PolyTrack) | 에셋 제작 비용(3D 모델링), 최적화 공수 | **✅ 채택(권장)** |
| B. 유사 3D (스프라이트 스케일링, 아웃런 방식) | 개발 가장 빠름, 초경량 | "초기 카툰 레이서" 감성보다 레트로 아케이드 감성. 드리프트 표현 한계 | 예비안 (A 리스크 시 전환) |
| C. 2D 탑다운 | 가장 단순 | 레이싱 몰입감·속도감 크게 손실 | ❌ |

### 성능 예산 (중급 폰 기준)
- 목표 60fps / 최저 30fps 보장 모드(저사양 자동 감지 시 그림자·파티클 축소)
- 씬 폴리곤 예산: 트랙+카트+소품 합계 **10만 폴리 이하**, 드로콜 100 이하
- 텍스처: 아틀라스 통합, 총 20MB 이하 (PWA 오프라인 캐시 부담 고려)
- 물리: 외부 물리엔진 미사용. **고정 타임스텝 커스텀 주행 모델**(아케이드 카트는 실물리보다 튜닝 곡선이 중요 + 아래 무결성 요건)

### 무결성 (기존 CELEB MATCH 방어 체계 확장)
- 기존 패턴 재사용: 서버 매치ID 발급 → **입력 로그(스티어·드리프트 타임라인) 기록** → 서버 결정론 리플레이 검증.
- 이를 위해 주행 물리는 **고정 타임스텝 + 결정론**으로 구현해야 한다(기기별 부동소수점 편차 방지 — 처음부터 리플레이 전제로 설계하는 것이 사후 도입보다 압도적으로 싸다).
- 고스트 재생 데이터 = 무결성 검증용 입력 로그와 동일 포맷(일석이조).
- 시행은 기존과 동일하게 **섀도우 관찰 → 데이터 축적 후 자동 거부 승격**.

### 통합 방식
- **별도 앱이 아니라 기존 game-app(PWA)에 신규 게임으로 통합** — SSO·CP 지갑·랭킹·미션·관리자 콘솔·무결성 인프라 전부 재사용. 별도 앱은 로그인/경제/운영이 이중화되어 비용만 늘어난다.
- 홈은 "게임 허브"로 개편 필요(퍼즐/레이싱 진입 카드). 허브 개편은 본 게임 W3에 포함.

## 9. 아트 방향

- CELEB MATCH 기존 톤 유지: **글로시 3D 캔디/젤리 + 바이올렛 네온** (기존 스타일 시트 참조).
- 카트: 로우폴리 + 큰 실루엣 + 원색. 멤버 식별은 카트 색·악기 모티프·헬멧 위 심볼로.
- 필요 에셋(런칭): 카트 3D 모델 5종, 트랙 3종(모듈식 도로 키트로 제작해 재사용), 부스터/드리프트 이펙트, 트랙별 스카이박스 3종, UI(속도계·랩·미니맵).
- 캐릭터 3D 제작이 부담이면 **1차는 "카트+헬멧 실루엣"만**(멤버 얼굴 3D 없이 식별) — 팬 민감도가 높은 멤버 얼굴 3D화는 품질 확보 전 시도하지 않는 것을 권장.

## 10. 제외 범위와 사유 (정직한 스코프)

| 제외 | 사유 |
|------|------|
| **충돌·아이템 상호작용형 실시간 멀티** | 충돌 판정 동기화는 전용 게임서버·넷코드가 필요한 별개 프로젝트 규모. 현 팀/인프라(서버리스+Supabase)와 불일치. **무충돌 라이브 고스트(§5)가 "함께 달리는 감각"을 현 인프라로 달성** — 충돌만 빼면 난이도가 급락한다는 것이 이 설계의 핵심 |
| 아이템전 | 실시간 상대 없이는 재미 불성립 (§4) |
| 가로 모드 | iOS 방향 잠금 불가(§2) — 세로 최적화에 집중 |
| 멤버 얼굴 3D | 품질 리스크 대비 이득 낮음. 카트·심볼로 식별 |
| 카트 성능 차등·강화 | 밸런스 운영 부담 + P2W 인상 리스크. 외형만 차등 |

## 11. 마일스톤 (검증 게이트 방식)

| 단계 | 산출물 | 게이트(통과 조건) |
|------|--------|-------------------|
| W0 프로토타입 | 그레이박스 트랙 1 + 주행/드리프트 모델 | **"조작이 재밌는가"** 내부 검증. 재미 없으면 주행 모델부터 재튜닝 (이 게이트 통과 전 아트 착수 금지) |
| W1 수직 슬라이스 | 트랙 1 완성 아트 + 카트 1 + 기록/랭킹 연동 | 60fps 실기 검증(중급 안드로이드+아이폰), 결정론 리플레이 일치 검증 |
| W2 콘텐츠 | 트랙 3 + 멤버 5 + 고스트 대전 + 미션 연동 | 무결성 섀도우 가동 |
| W3 폴리시·베타 | 온보딩, 사운드, 신기록 연출, 홈 허브 개편 | 베타 배포 → 유저 피드백 1주 → 정식 |

- 각 단계 종료 시 사용자 승인 후 다음 진행 (기존 배포 원칙과 동일).

## 12. 리스크와 완화

| 리스크 | 확률 | 완화 |
|--------|------|------|
| 주행 손맛 미달 (가장 큰 리스크) | 중 | W0 게이트에서 판정. 미달 시 유사 3D(B안)로 전환하고 스프라이트 감성으로 재포지셔닝 |
| 저사양 기기 프레임 저하 | 중 | 성능 예산 사전 고정 + 저사양 모드 자동 전환 |
| 결정론 리플레이 기기별 불일치 | 중 | 고정 타임스텝+정수/고정소수 연산 설계, W1 게이트에서 다기종 검증. 불일치 시 서버 검증은 구간 기록 대조(체크포인트 방식)로 완화 |
| 3D 에셋 제작 지연 | 중 | 모듈식 트랙 키트로 제작량 축소, W0는 그레이박스로 진행 |
| iOS 오디오/PWA 이슈 | 저 | CELEB MATCH에서 이미 해결한 패턴 재사용 |

## 13. KPI (베타 기준)

- 첫 완주율 ≥ 85% (튜토리얼 트랙)
- 판당 평균 재도전 횟수 ≥ 2.5 (고스트 루프 작동 지표)
- D1 리텐션: CELEB MATCH 단독 대비 +5%p (허브 시너지 지표)
- 프레임: 중급 기기 60fps 유지율 ≥ 90%

## 14. 오픈 이슈 (사용자 결정 필요)

1. 영문 표기 확정 (CELEB RUSH 권장) + 상표 출원 확인(KIPRIS)
2. W0 프로토타입 착수 승인 여부와 시점
3. 멤버 카트 모티프 확정 (멤버별 악기 매핑은 실제 포지션 기준: 유찬=드럼, 주연=마이크, 케빈=키보드, 지섭=기타, 노스케=베이스)
4. 데일리 코스 모드의 1차 포함 여부
