# [QA 검토 메모] 일일미션(DLY)

> 파일럿 QA(`CELEBUS BO 단위테스트 v1.0.xlsx` / 시트 `일일미션`, 57 TC) 작성 기준과 논의 사항.

## 작성 기준 (확정)
- **로직·플로우·정책 = 문서(v2/BO 명세 + [CEB-000] 공통 정책)** 가 표준. TC의 테스트 내용·예상결과·검증 규칙은 전부 문서 근거.
- **카테고리(시트·Depth1~3) = 프로토타입에 구현된 메뉴** 구조(`AdminSidebar.tsx`). 프로토타입은 "어떤 메뉴·화면이 존재하는가"의 분류 틀로만 사용하며, 동작의 근거로 삼지 않는다.
- DLY는 프로토 사이드바에서 Depth1 단일 메뉴 `일일미션`(`/daily-missions`) → 시트 1개.

## 1. 모달 — 문서 서술 기준으로 전수 반영
문서상 별도 화면ID가 부여된 모달은 2종이지만, 본문(§2.5·§4·§5)에 **추가 확인 동작이 서술**되어 있어 QA에 모두 포함:
| 모달/다이얼로그 | 문서 근거 | 화면ID |
| --- | --- | --- |
| 미션 추가·수정 | [DLY-101-MD-MISSION] | 있음 |
| 미션 삭제 확인(0건화 경고 포함) | [DLY-101-MD-DELETE] §본문 | 있음 |
| 사용여부 토글 0건화 확인 | [DLY-101] §4·§5 | 별도ID 없음(본문 서술) |
| 설정·스트릭 변경 요약 확인 | [DLY-101] §2.5 | 별도ID 없음(본문 서술) |
- → 일반 QA 기준상 확인 다이얼로그는 별도 화면ID 없이 부모 화면 TC로 커버하는 것이 표준. ID 부여는 QA 전제조건이 아니라 기획 문서 완성도 차원의 선택 사항(필요 시 추후 정리).

## 2. 테스트 환경 안내 (TC 유효성과 무관)
아래는 **TC 자체는 문서 기준으로 유효**하되, 실행 환경상 검증 시점이 다른 항목(테스터 운영 참고용):
| 분류 | 해당 항목 | 검증 시점 |
| --- | --- | --- |
| 앱 연동(P3 10건) | 앱[CEB-FQ-501] 반영·소급 없음·다음날 자정 | 앱 빌드 연동 단계 |
| 활동 로그 | 추가/수정/삭제/토글/설정 로그 | SYS 활동로그 연동 단계 |
| 서버 에러·시간 기준 | 조회/저장 실패·자정 리셋·당일 배정 보존 | 실서버 단계 |
> 분류 컬럼이 아니라 '테스트 항목'(앱 연동 확인·백오피스 액션·에러 메시지 확인) 명으로 식별 가능.

## 3. 확장 시 동일 적용
다른 영역도 동일 원칙: **카테고리=프로토 사이드바 메뉴**, **내용=문서**. 프로토에 메뉴가 아직 없는 문서 화면, 반대로 프로토에만 있고 문서 미정인 메뉴가 있으면 그 갭을 메모로 표기 후 논의.
