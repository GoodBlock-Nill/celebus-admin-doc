## 4. 재설계 — 회원 플로우

| 영역 | 현재 | 개선 |
|---|---|---|
| 오입금(금액 불일치) | 미대조 입금으로 침묵, 주문은 입금 대기 유지 (B-2) | **자동 확인 보류 전환**: 동일 실명(또는 실명+예매번호) 입금이 금액만 다르면 주문을 확인 보류로 자동 전환 + 표준 사유 코드(입금자명/금액/복합 — 문자열 키워드 의존 제거, B-3) → 회원에게 즉시 해결 카드 노출 |
| 자동 만료 | 확인 보류도 마감 시 자동 취소 (C-1) | **연결 입금이 있는 주문은 자동 만료 제외** (원칙 1). 만료 문구도 "입금이 확인되지 않아"를 상태별로 정정 |
| 취소 요청 | 즉시 접수, 계좌 수집 없음 (E-2) | **취소 요청 단계에 환불 계좌 입력**(기존 보류용 폼 재사용 — 서버 함수는 이미 취소 요청 상태 제출 허용). 미입력 시 접수는 받되 "계좌 등록 전 환불 불가" 안내 + 상세에서 상시 등록 가능 |
| 보류 반려 후 | 계좌 등록 경로 소멸 (C-5) | **환불 예정 이력이 있는 주문은 상태 무관 계좌 등록 허용** — 반려 안내 박스에 [환불 계좌 등록] 진입 부착 |
| 입금확인 요청 남용 | 무한 반려↔재요청 (B-11) | 재요청 횟수 제한(예: 3회) + 반려 누적 시 고객센터 안내로 전환. 마감+유예 상한(예: 반려 후 24시간) 병행 |
| 중복 신청 | 재시도 시 이중 선점 (A-10) | 신청 멱등키(회차+회원+진행중 주문 존재 검사) — 진행중 주문이 있으면 기존 주문으로 안내 |

## 5. 재설계 — 관리자 "주문 중심 작업함"

기존 5탭(입금 확인 요청/확인 대기/티켓 지급 대기/보류/환불 대상, 입금 건·주문 기준 혼재)을 **3구획**으로 재구성:

1. **할 일 (주문 단일 큐)** — 처리 필요한 주문만 우선순위 정렬(회원 요청 → 자동 대조 완료 → 보류 → 환불 대기). 행 확장 시 해당 주문의 전체 맥락(요청 시각·회원이 알린 정보·연결 입금 전부·활동 이력)을 한곳에 표시. 상황별 **권장 액션 1개 강조**:
   - 요청 주문: [은행 내역 대조] 인라인 입력 → 일치 시 등록+대조+입금 확인 **원클릭**, 불일치 시 자동 보류+표준 사유
   - 보류 주문: [입금 확인(인정)] / [보류 반려] 택일 · 복수 입금 연결 시 건별 [반환 대상 지정] 노출(B-7 해소)
   - 취소 요청: [환불 승인(계좌 확인 포함)] / **[취소 요청 반려]**(신규, E-1)
   - 오처리 정정: 입금 확인 취소·티켓 지급 취소 역방향 액션(신규, C-6 — 권한·로그 필수)
2. **공연 당일 지급** — 회차 선택 → D-day·지급 대상 n건 요약 → **[일괄 지급]** + 미지급 경고 배지(D-4)
3. **주문 조회 + 주문 미상 입금 + 처리 이력** — 전체 주문 검색(예매번호·실명·상태 — 만료·지급 완료 포함, D-8), 주문 미상 입금 처리(수동 매칭·반환), 이력
- 공연 관리에 **[공연 취소 — 전체 환불 전환]** 액션 신설(D-3): 해당 공연 주문 일괄 취소 요청 전환 + 티켓 회수 + 회원 계좌 수집 안내 발송
