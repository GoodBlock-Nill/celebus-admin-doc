## 목적

이 문서는 CELEBUS v2 시스템 백오피스(BO) 전반에 걸쳐 반복 등장하는 **공통 정책, 규칙, 규격**을 한 곳에 정의한다. 화면 명세 작성 전에 BO 운영 표준을 먼저 확정하여, 모든 BO 화면이 일관된 권한·다국어·로그·UI 상태·검수 워크플로우를 따르게 한다.

> 각 BO 화면 스펙 문서는 **화면 고유 로직만** 기술하고, 공통 정책은 본 문서를 참조한다.
> 공통 정책 변경 시 본 문서만 수정한다.

> v2 앱 공통 정책 [CEB-000]과 별도지만 호환되는 BO 정책 체계이다. 사용자 노출 정책(다국어 라벨·토스트·UI 상태)은 [CEB-000]과 동일/하위 호환 유지.

## 1. 개요

### 1.1 BO 정의·범위

| 항목 | 내용 |
| --- | --- |
| BO 명칭 | CELEBUS Admin (v2) |
| 대상 사용자 | 본사 운영팀·기획팀·마케팅팀 + 외부 권한자 (아티스트사) |
| 접근 방식 | 웹 (PWA 별도 / 데스크톱 우선) |
| 인증 | 이메일 + 비밀번호 + 2FA (운영자 이상 필수) |

### 1.2 v2 BO 서비스 영역

> 영역 구분은 **현재 백오피스에 실제 노출된 메뉴**를 기준으로 한다. 상세 매핑은 [CEB-BO-001] 참조. 멀티아티스트 운영 정책은 [CEB-BO-100] 참조.

| 메뉴 (백오피스) | 접두어 | 영역 가이드 | 주요 관리 |
| --- | --- | --- | --- |
| 회원 | `USR` | [CEB-BO-002] | 회원 리스트·상세·검색·필터·제재·자산 회수 |
| 아티스트 (그룹·멤버) | `ART` | [CEB-BO-003] | 그룹·멤버·소속사·포지션·활동 |

| 기억저장소 | `MEM` | [CEB-BO-MEM-000] | 감정 이모지 관리 (아티스트별 · 유니코드/커스텀 이미지). 신고·차단은 후속 |

> **준비 중(정책 정의 후속)**: 대시보드 · 프로젝트 · Fans · 티켓 · 재무 — 메뉴는 노출되나 화면·정책 미확정이라 본 문서 정책 대상에서 제외.

### 1.3 [CEB-000] 앱 공통 정책과의 관계

- BO에서 입력하는 **사용자 노출 텍스트·이미지·자산**은 모두 [CEB-000] 앱 공통 정책의 표기·규격을 따름.
- 다국어 라벨(`§1.3`)·푸시 알림 정책(`§15`)·토스트 규격·UI 상태 등은 양 문서에서 모순 없도록 동기화.
- BO 한정 메타 정책(권한·로그·검수 워크플로우)은 본 문서에서만 정의.

## 2. 화면 ID 체계

### 2.1 패턴

```
CEB-BO-{서비스}-{번호}[-{유형}]
```

| 구성 | 설명 | 예시 |
| --- | --- | --- |
| `CEB-BO-` | 백오피스 고정 접두어 | — |
| `{서비스}` | 영역 접두어 (USR·ART·INF·EVT·SUP·APP·BIVE·GZ·SQ·RFL·RFT·SYS) | `SQ` |
| `{번호}` | 영역 내 화면 번호 (3자리) | `101` |
| `{유형}` | (선택) 화면 유형 — `Create` / `Edit` / `MD-{action}` | `MD-DELETE` |

**전체 예시**:
- `CEB-BO-SQ-302` — 팬퀘스트 리스트 (List)
- `CEB-BO-SQ-302-CREATE` — Quest 생성
- `CEB-BO-SQ-303-MD-OPEN` — Quest 게시 모달
- `CEB-BO-EVT-101` — 팬덤 레벨 리스트
- `CEB-BO-RFL-203-MD-DRAW` — 래플 추첨 모달

### 2.2 번호 분배 규칙

| 번호대 | 용도 |
| --- | --- |
| `100` | 메인 List (서비스 진입 화면) |
| `101~199` | 메인 List 하위 화면 (Create·List 변형 등) |
| `201~299` | Detail (탭별 또는 단일) |
| `301~399` | 부속 관리 화면 (예: 반려사유 설정·이력) |
| `401~499` | 내역 조회 (제출 이력·변동 내역 등) |
| `501~599` | 정책 설정 (시즌·캡·곡선 등) |
| `601~699` | 외부 연동·API 관리 (필요 시) |
| `MD-{action}` | Modal — 부모 화면 ID 뒤에 붙임 |

### 2.3 v1 문서와의 관계

| 항목 | v1 문서 | v2 (현재) |
| --- | --- | --- |
| 게임존 | `CEB-BO-GZ-*` | 동일 ID 유지 — v2 게임존 메뉴로 활성 운영 |
| 팬퀘스트 | `CEB-BO-FQ-*` | 에피소드(`CEB-BO-SQ-*`) + 래플(`CEB-BO-RFL-*`) + 응모권(`CEB-BO-RFT-*`)로 분해 이전 |

> 게임존(GZ)은 v1 화면 ID 체계를 그대로 유지하며 v2 백오피스 메뉴로 운영한다. 구 팬퀘스트(FQ) 문서는 v2에서 에피소드·래플·응모권 영역으로 재구성되었으며 `CEB-BO-FQ-*` ID는 더 이상 사용하지 않는다.

## 3. 권한 체계

v2 BO 권한은 **권한 그룹 기반**으로 운영한다. 고정된 권한 등급이 아니라, 관리자별로 배정된 권한 그룹의 설정에 따라 영역별 읽기·쓰기·삭제 범위가 결정된다.

| 항목 | 정의 위치 |
| --- | --- |
| 권한 그룹 목록·생성 | [CEB-BO-SYS-102] 권한 그룹 리스트 |
| 그룹별 영역 읽기·쓰기·삭제 범위, 소속 관리자 | [CEB-BO-SYS-202] 권한 그룹 상세 |
| 영역·기능 단위 세부 권한 | [CEB-BO-SYS-501] 권한 스코프 |
| 관리자별 권한 그룹 배정·부여·회수 | [CEB-BO-SYS-201] 관리자 상세 |

- 권한 부여·회수·변경은 모두 활동 로그에 자동 기록한다(§6).
- 외부 협력사(아티스트사) 관리자는 **자기 아티스트 한정** 접근으로 제한되며, 적용 범위는 권한 그룹 설정과 멀티아티스트 마스터 [CEB-BO-100]를 따른다.

> 개별 화면 명세는 권한 등급 표를 다시 정의하지 않고 "권한은 [CEB-BO-SYS-102] 권한 그룹 설정에 따른다"로 참조한다.

## 4. 영역별 접근 범위

영역별 읽기·쓰기·삭제 허용 범위는 권한 그룹마다 다르게 설정하며, 구체적 매트릭스는 [CEB-BO-SYS-202] 권한 그룹 상세에서 그룹 단위로 관리한다. 본 공통 정책은 고정 매트릭스를 정의하지 않는다.

- 사이드 메뉴는 접근 권한이 있는 영역만 노출한다(§7.2).
- 외부 협력사 관리자는 매핑된 아티스트의 데이터만 검색·조회·편집할 수 있으며, 그 외 아티스트 데이터는 검색 결과·직접 접근 모두 차단한다.

## 5. 다국어 입력 정책

### 5.1 KO/EN/JP 3언어 동시 필수

**모든 사용자 노출 텍스트**(타이틀·설명·라벨·CTA·안내 문구)는 KO/EN/JP 3개 언어 모두 입력해야 한다.

| 항목 | 정책 |
| --- | --- |
| 필수 입력 | KO·EN·JP **3개 모두** |
| 빈 칸 검증 | 1개 이상 빈 칸 → 저장 차단 + 토스트(Error) "모든 언어 필드를 입력해주세요" |
| 저장 시점 | 임시저장(Draft)도 3언어 모두 입력 권장. 단, **임시저장은 1개 언어만 입력해도 허용** (게시 시점에 3언어 강제 검증) |
| 게시 차단 | 게시(Publish) 시 3언어 빈 칸 검증 → 미충족 시 게시 불가 |
| 글자수 제한 | 필드별로 화면 명세서에 명시 (예: 타이틀 50자, 설명 500자) — 모든 언어 동일 적용 |

### 5.2 글자수 제한 필드 기준

다국어 입력 필드의 **표준 글자수 제한**. 화면 명세 작성 시 본 표를 기준으로 일관 적용. 모든 언어(KO/EN/JP) 동일 적용.

| 필드 유형 | 글자수 제한 | 비고 |
| --- | --- | --- |
| **타이틀** (Quest·Raffle·이벤트·소식 등) | **50자** | 카드·리스트 노출용 짧은 제목 |
| **상세설명** | **500자** | 본문 설명. 줄바꿈 포함 |
| **결과·정답 텍스트** (PM 결과·SETLIST 정답 등) | **50자** | 단답형 |
| **반려사유 텍스트** (운영자 추가 메시지) | **200자** | 코드 외 자유 입력 보충 |
| **카드 라벨·뱃지명** | **20자** | 짧은 표기 |
| **CTA 버튼 텍스트** | **15자** | 행동 유도 짧은 문구 |
| **링크 텍스트** | **30자** | 링크 표시 텍스트 |
| **알림·푸시 메시지** | **80자** | 모바일 알림 절단 방지 |
| **약관·안내문** | **2,000자** | 긴 본문. 줄바꿈·단락 포함 |
| **운영자 메모** (내부 관리용) | **500자** | KO만, 비공개 |

**화면 명세에서 다른 글자수가 필요하면**: 해당 화면 스펙 문서 §UI 구성 표에 명시. 본 표는 기본값.

**검증 정책**:
- 글자수 초과 입력 차단 + 입력 필드 카운터 빨간색 표시 (`{현재}/{제한}`)
- 글자수 90% 도달 시 카운터 주황색 경고
- 줄바꿈도 1자로 카운트
- 이모지·특수문자도 1자로 카운트 (multi-byte 무관)

## 6. 관리자 활동 로그

모든 BO 작업(쓰기·삭제·승인·반려·권한 변경)은 활동 로그에 자동 기록된다.

### 6.1 로그 필수 필드

| 필드 | 내용 | 예시 |
| --- | --- | --- |
| 일시 | YYYY.MM.DD HH:mm:ss (KST) | 2026.05.05 14:32:18 |
| 권한 그룹 | 작업자가 속한 권한 그룹명 | 콘텐츠 운영 그룹 |
| 작업자 | 이메일 | nill@celebus.xyz |
| 영역 | 영역명 | 에피소드 |
| 액션 | 생성·수정·삭제·승인·반려·게시·종료 등 | 승인 |
| 대상 | 화면 ID + 대상 ID | CEB-BO-SQ-304 / 팬퀘스트 제출 #1042 |
| 변경 내용 | 자유 텍스트 (변경 전/후 자동 기록 또는 운영자 수동 입력) | 보상 50덕력 → 75덕력 |
| IP | 접속 IP | 1.2.3.4 |

### 6.2 영역별 활동 로그 메시지 템플릿

| 영역 | 액션 | 로그 메시지 (KO) |
| --- | --- | --- |
| 에피소드 | 생성 | 팬퀘스트 '{타이틀}' 생성 (보상: 응모권 {N}장 + 디지털 포토카드 {N}장) |
| 에피소드 | 검수 승인 | 팬퀘스트 제출 #{ID} 승인 (작업자: {이메일}, 보상 자동 지급) |

| 운영 시간 | **평일 09:30 ~ 18:30 KST** (공휴일 제외) |
| 처리 목표 | **24시간 내** (운영 시간 기준 — 금요일 18:30 이후 제출은 월요일까지) |
| 유저 안내 | 제출 직후 "하루 안에 결과를 알려드릴게요" 안내. 24시간 초과 시 자동 알림 "조금 더 시간이 걸려요" |
| 우선순위 | ① 캠페인 마감 임박 항목 (D-3 이내) ② 일반 ③ 재제출 (반려 후 재도전) |
| 한계 (1인) | 한 운영자가 1시간 내 검수 가능 권장량: **50건 이하** (피로 누적 방지) |

#### 운영자 간 인계

| 시나리오 | 처리 |
| --- | --- |
| 검수 중 휴가·퇴근 | "내가 잠금 중인 항목 일괄 해제" 버튼 → 다음 운영자가 이어 검수 |
| 인계 노트 | 항목별 운영자 메모 (KO 만, 200자) — 다음 운영자에게 전달용 |
| 의심 케이스 인계 | "운영 매니저 검토 요청" 플래그 → SUPER가 별도 큐에서 확인 |
| 일괄 처리 한도 | 일괄 승인은 한 번에 최대 **20건**. 일괄 반려는 한 번에 최대 **10건** (반려사유 일괄 적용) |

#### 검수 품질 관리

- **샘플링 감사**: SUPER가 OPERATOR 검수 결과를 무작위 샘플링 감사. 잘못 승인·반려 발견 시 시정 + 활동 로그 기록.
- **반려율 모니터링**: OPERATOR별 반려율 통계. 비정상적으로 높거나 낮으면 검토.
- **유저 이의 제기**: 반려 후 유저가 이의 제기 가능 (CS 채널). SUPER가 재검토 후 결정.

### 12.3 임시저장·자동 복구

| 항목 | 정책 |
| --- | --- |
| 자동 저장 트리거 | Form 입력 변경 후 30초 idle. 변경 사항 없으면 미작동 |
| 저장 위치 | 서버 저장 (브라우저 임시 저장 보조). 모든 운영자 단말 동기화 |
| 복구 트리거 | 화면 재진입 시 "이어서 작성하시겠어요?" 모달 → [이어쓰기] / [새로 시작] |
| 복구 가능 기간 | **자동 저장 후 7일** (이후 자동 삭제) |
| 다국어 입력 | 부분 입력 (KO만)도 자동 저장 OK. 게시 시점에 3언어 검증 |
| 충돌 처리 | 다른 운영자가 같은 항목 자동 저장한 경우 → "다른 사용자 변경 사항이 있습니다" 경고 + 비교 화면 |
| 임시저장(Draft) 차이 | "자동 저장"은 시스템 내부 백업. "임시저장(Draft)"은 운영자 명시 저장 — 서로 별개 |

### 12.4 동시 수정 충돌 처리

여러 운영자가 같은 항목을 동시 수정하는 경우.

| 시나리오 | 처리 |
| --- | --- |
| 동일 항목 Edit 진입 | 두 번째 진입자에게 "현재 {운영자명}이 수정 중입니다" 경고 표시. 진입 가능하나 저장 시 충돌 발생 가능 |
| 검수 중 잠금 | OPERATOR 검수 시 5분 idle 잠금 (`§10` 기준). 다른 운영자 진입 시 "검수 잠금 중" 표시 |
| 저장 시 충돌 감지 | 저장 시 `version` 비교. 다른 운영자가 먼저 저장 시 → 토스트(Error) "다른 운영자가 변경했습니다. 최신 상태를 확인하세요" + [최신 새로고침] |
| 충돌 해결 UI | "내 변경 사항 vs 최신 상태" 비교 화면 (좌·우 분할). 운영자가 항목별 선택 후 재저장 |
| 자동 병합 | 다른 필드 수정인 경우 자동 병합 시도. 같은 필드 충돌 시에만 수동 해결 요청 |

### 12.5 삭제 복구 정책

BO에서 삭제된 데이터의 **복구 가능 기간**과 **권한**.

| 영역 | 삭제 유형 | 복구 가능 기간 | 복구 권한 |
| --- | --- | --- | --- |
| Quest·Raffle | 논리 삭제 (soft delete) | **30일** | SUPER만 |
| 콘텐츠 (소식·일정) | 논리 삭제 | 30일 | SUPER만 |
| 디지털 굿즈 | 논리 삭제 | **90일** (지급 이력 추적) | SUPER만 |
| 회원 계정 | 논리 삭제 (탈퇴 처리) | **30일 유예 후 물리 삭제** (개인정보보호법 준수) | 자동 / SUPER 강제 |
| 활동 로그 | 삭제 불가 (append-only) | — | — |
| 권한 변경 이력 | 삭제 불가 | — | — |

**복구 절차**:
1. SUPER가 [삭제 항목 조회] 메뉴에서 삭제된 항목 검색
2. 항목 선택 → [복구] 버튼 → 복구 사유 입력 (필수, 100자)
3. 복구 즉시 활동 로그 자동 기록
4. 복구된 항목은 이전 상태(예: 임시저장)로 복원

**물리 삭제**:
- 복구 가능 기간 경과 시 자동 물리 삭제 (DB에서 완전 삭제, 복구 불가)
- 회원 정보는 개인정보보호법에 따라 30일 후 물리 삭제 강제

## 14. 회원 제재 정책

위반 행위 적발 시 회원에 대한 제재를 BO에서 운영한다. 모든 제재는 활동 로그 자동 기록.

### 14.1 위반 행위 코드

| 코드 | 위반 유형 | 설명 | 기본 제재 |
| --- | --- | --- | --- |
| `V_ABUSE` | 어뷰징 (다중 계정·자동화) | 동일 인물의 여러 계정 운영, 봇 사용 | 영구 정지 |
| `V_DUPLICATE` | 중복 제출·반복 부정 | 동일 캡처 반복 제출 | 7일 정지 → 영구 정지 (3회 누적) |
| `V_TRANSFER` | 계정 양도·매매 | 응모권·당첨 권리 양도 의심 | 영구 정지 + 당첨 취소 |
| `V_FRAUD` | 사기·기망 | 허위 정보 입력, 타인 도용 | 영구 정지 |
| `V_HARASSMENT` | 괴롭힘·혐오 | 기억저장소·댓글 공격 | 30일 정지 → 영구 정지 |
| `V_INAPPROPRIATE` | 부적절한 콘텐츠 | 음란·폭력·차별 콘텐츠 | 게시물 삭제 + 7일 정지 |
| `V_COPYRIGHT` | 저작권 침해 | 무단 도용 콘텐츠 | 게시물 삭제 + 경고 |
| `V_SPAM` | 스팸·광고 | 외부 링크 무단 배포 | 게시물 삭제 + 경고 |
| `V_OTHER` | 기타 | 운영자 직접 입력 | 운영자 판단 |

### 14.2 제재 단계

| 제재 | 효과 | 권한 |
| --- | --- | --- |
| **경고** (Warning) | 안내 메시지 발송. 제재 이력에만 기록. 서비스 이용 가능 | OPERATOR |
| **부분 정지** (Partial Restriction) | 특정 기능만 차단 (예: 기억저장소 작성 금지, 댓글 금지) | OPERATOR |
| **임시 정지** (Suspension) | 1·7·30·90일 — 로그인 가능하나 활동 차단. 응모권 사용·신규 응모 불가 | OPERATOR (1·7일) / SUPER (30·90일) |
| **영구 정지** (Permanent Ban) | 로그인 불가. 모든 활동 차단. 보유 자산 소멸 | SUPER만 |
| **당첨 취소** | 진행 중·완료된 당첨 권리 회수 | SUPER만 |
| **계정 삭제** | 회원 정보 삭제 (개인정보보호법 30일 유예) | SUPER만 |

### 14.3 제재 처리 절차

```
위반 적발 (자동 탐지·신고·운영자 인지)
    ↓
[CEB-BO-USR-201] 회원 상세 → [제재 처리] 버튼
    ↓
모달: 위반 코드 선택 + 제재 단계 선택 + 사유 텍스트 (필수, 200자)
    ↓
저장 → 즉시 적용 + 회원에게 알림 + 활동 로그 기록
    ↓
회원이 이의 제기 시: SUPER 재검토 → 제재 해제 또는 유지 결정
```

### 14.4 제재 해제·복구

| 항목 | 정책 |
| --- | --- |
| 자동 해제 | 임시 정지는 기간 만료 시 자동 해제 |
| 수동 해제 | SUPER가 [제재 해제] 버튼으로 즉시 해제. 사유 필수 |
| 영구 정지 해제 | SUPER만 가능. 매우 신중하게 — 활동 로그에 해제 사유 상세 기록 |
| 당첨 권리 복구 | 잘못된 제재로 당첨 취소된 경우 SUPER가 수동 복구 |
| 보유 자산 복구 | 영구 정지 시 소멸된 응모권·덕력은 해제 시 자동 복구되지 않음 (별도 운영 결정) |

### 14.5 제재 이력 조회

- 모든 제재는 회원 상세 화면([CEB-BO-USR-201])의 [제재 이력] 탭에서 회원별로 조회
- 활동 로그와 별도로 제재 이력 전용 보관 (3년)

| 입력 정보 | 이름·유형(충전/출금)·주소·Private Key (암호화 저장) |
| Private Key 저장 | **암호화 저장 + DB 분리 보관**. BO 화면에서는 마스킹 (`0x...****...`) |
| Private Key 조회 | SUPER만 가능. 조회 시 2FA 추가 인증 + 활동 로그 기록 |
| 잔액 표시 | 실시간 BNB·CELB 잔고 표시. 5분마다 자동 갱신 |
| 비활성화 | 거래 중단 시 비활성화 가능. 잔액 0 또는 다른 지갑으로 이체 후 |

## 16. BO 푸시·알림 정책

BO에서 회원에게 발송하는 푸시·앱 알림 운영 정책.

### 16.1 발송 권한

| 발송 유형 | 권한 | 비고 |
| --- | --- | --- |
| 자동 푸시 (시스템 트리거) | 자동 | 검수 승인·당첨·보상 지급 등 — 시스템이 자동 발송 |
| 수동 푸시 (캠페인) | SUPER + POLICY | 캠페인 안내·이벤트 알림 등 — 운영자 수동 발송 |
| 긴급 공지 푸시 | SUPER만 | 점검·장애·보안 등 |

OPERATOR는 **자동 푸시만** (검수 승인 시 자동 발송). 임의 캠페인 푸시 발송 권한 없음.

### 16.2 푸시 메시지 템플릿

| 시나리오 | 템플릿 (KO) | 영역 |
| --- | --- | --- |
| 팬퀘스트 검수 승인 | "팬퀘스트 '{타이틀}' 승인! 응모권 {N}장 + 디지털 포토카드 1장이 지급됐어요 🎁" | 에피소드 |
| 팬퀘스트 검수 반려 | "팬퀘스트 제출이 반려됐어요. 사유: {반려사유 메시지}. 다시 제출해보세요!" | 에피소드 |
| 래플 당첨 | "🎉 {래플 명} 당첨을 축하드려요! 자세한 안내는 메일을 확인하세요" | 래플 |
| 덕력 적립 | "덕력 +{N}DUK 획득! 현재 잔액: {잔액}DUK" | 덕력관리 |
| 팬덤 레벨업 | "🎊 {아티스트명} 팬덤이 Lv.{N}에 도달했어요! 보상을 확인하세요" | 팬덤레벨 |
| 서포트 이벤트 달성 | "🎉 '{이벤트명}' 응원 목표 달성! 결과물이 곧 공개돼요" | 서포트 |
| 응모권 만료 안내 | "보유 응모권 {N}장이 곧 만료돼요. ({만료일}까지)" | 응모권 |

각 템플릿은 KO/EN/JP 3언어 동시 작성 (`§5` 적용). 변수 `{N}·{타이틀}` 등은 발송 시점에 치환.

### 16.3 수동 푸시 발송 절차

수동 푸시·앱 알림은 [앱 > 알림 관리] 영역에서 작성·발송한다. 작성 화면은 [CEB-BO-APP-302] 알림 상세·작성, 반복 문구는 [CEB-BO-APP-303] 알림 템플릿 관리를 사용한다.

```
[CEB-BO-APP-302] 알림 상세·작성
    ↓
대상 선정 (전체·아티스트별·등급별·기간 활동·태그 등)
    ↓
메시지 입력 (KO/EN/JP 3언어 + 클릭 시 이동 링크)
    ↓
미리보기 (모바일 화면 시뮬레이션)
    ↓
발송 시점 (즉시 발송 / 예약 발송)
    ↓
[발송] → 2차 확인 모달 → 최종 발송
    ↓
발송 결과 자동 집계 (수신·표시·클릭 수)
```

### 16.4 발송 한도·SPAM 방지

| 항목 | 정책 |
| --- | --- |
| 회원당 푸시 한도 | 1일 최대 5회 (시스템 자동 + 캠페인 합산) |
| 캠페인 푸시 한도 | 1일 1회 (전체 발송 기준) |
| 야간 발송 차단 | 22:00~08:00 KST 발송 차단 (긴급 공지 제외) |
| 수신 거부 | 회원이 푸시 알림 끄기 가능 (시스템 알림은 강제 발송) |
| 다국어 매칭 | 회원 앱 언어 설정에 따라 자동 매칭 발송 |

### 16.5 발송 로그

- 모든 푸시 발송은 로그 보관 (3년)
- 로그 항목: 발송 시각·발송자(시스템 또는 운영자 이메일)·대상 수·수신 성공/실패·클릭률
- 전체 발송 로그는 [CEB-BO-APP-301] 알림 관리에서 조회 (최고 권한 그룹)

### 16.6 발송 실패 재시도

| 실패 유형 | 재시도 |
| --- | --- |
| 일시적 네트워크 오류 | 자동 재시도 (3회, 지수 백오프) |
| 토큰 만료 | 자동 토큰 갱신 후 재시도 |
| 회원 비활성·탈퇴 | 재시도 안 함. 로그에 "수신 불가" 기록 |
| FCM/APNs 오류 | 운영자 알림 + SUPER 검토 |

## 17. 미디어 업로드 규격

BO에서 등록하는 이미지·영상·파일의 표준 규격.

### 17.1 이미지 업로드

| 항목 | 정책 |
| --- | --- |
| 지원 포맷 | JPG / PNG / WebP / SVG (벡터) |
| 최대 용량 | 10 MB (배너·포스터) / 5 MB (일반) / 2 MB (썸네일·아이콘) |
| 권장 해상도 | 화면 명세서별 명시. 일반: 1080×1080 (정사각) / 1080×1920 (세로) / 1920×1080 (가로) |
| 자동 리사이징 | 업로드 시 썸네일 자동 생성 (300×300, 600×600) |
| 자동 압축 | JPG 품질 85, PNG 무손실 최적화 |
| 알파 채널 | PNG·WebP·SVG는 투명 배경 지원 |
| 메타데이터 | EXIF 자동 제거 (개인정보 보호) |

### 17.2 영상 업로드

| 항목 | 정책 |
| --- | --- |
| 지원 포맷 | MP4 (H.264 + AAC) / MOV |
| 최대 용량 | 100 MB (홍보영상·릴스용) |
| 최대 길이 | 60초 (BO 직접 업로드). 더 긴 영상은 외부 CDN URL 등록 권장 |
| 권장 해상도 | 1080×1920 (세로 9:16) / 1920×1080 (가로 16:9) |
| 자동 썸네일 | 영상 첫 프레임 자동 캡처 |
| 자동 트랜스코딩 | 다양한 해상도 변환 (480p·720p·1080p) |

### 17.3 파일 업로드 (문서·CSV 등)

| 항목 | 정책 |
| --- | --- |
| 지원 포맷 | PDF·CSV·XLSX·TXT·JSON |
| 최대 용량 | 50 MB |
| 보안 검사 | 업로드 시 자동 바이러스 스캔 |
| 보관 기간 | 영구 (또는 운영자 수동 삭제까지) |

### 17.4 업로드 동작

| 시나리오 | 처리 |
| --- | --- |
| 업로드 중 | 진행률 바 + 취소 버튼 |
| 업로드 실패 | 토스트(Error) "업로드 실패. 다시 시도하세요" + 자동 재시도 1회 |
| 용량 초과 | 토스트(Error) "최대 {N}MB까지 가능합니다" + 업로드 차단 |
| 포맷 불일치 | 토스트(Error) "지원하지 않는 파일 형식입니다 ({지원 목록})" |
| 보안 검사 실패 | 토스트(Error) "보안 위험이 감지됐습니다. 운영진에 문의하세요" + 운영진 자동 알림 |
| 중복 업로드 | "동일한 파일이 이미 등록돼 있어요. 그래도 등록할까요?" 확인 모달 |
