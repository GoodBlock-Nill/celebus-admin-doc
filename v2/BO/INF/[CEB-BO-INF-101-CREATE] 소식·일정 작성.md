## 1. 화면 목적

신규 소식·일정·공지를 작성하는 입력 폼. 운영자가 타입을 선택해 타입별 항목을 입력하고, 임시저장하거나 즉시 게시한다. 입력 항목 구성은 [CEB-BO-INF-201-EDIT] 소식·일정 수정과 동일하며, 작성 화면은 빈 폼으로 진입한다.

## 2. UI 설명

### 2.1 헤더

- Breadcrumb: `홈 > 아티스트 > 소식/일정 > 작성`
- 타이틀: 소식/일정 작성
- 우측 상단 액션: [취소] / [임시저장] / [게시]
- **[게시]는 다국어 필수(한국어·영어·일본어)와 타입별 필수 항목이 모두 충족될 때만 활성**된다. 미충족 시 비활성으로 처리하고, 헤더 하단에 미충족 사유 안내 문구를 노출한다(아래).
- [임시저장]은 미완성 상태에서도 항상 가능하다.

| 안내 문구 (미충족 시) | 표시 위치 |
| --- | --- |
| 소식·공지: "게시하려면 제목·본문의 한국어·영어·일본어를 모두 입력하세요. (임시저장은 가능)" | 헤더 하단 |
| 일정: "게시하려면 제목의 한국어·영어·일본어와 일시를 모두 입력하세요. (임시저장은 가능)" | 헤더 하단 |

### 2.2 공통 메타 (사이드 — 설정)

| 항목 | 형식 |
| --- | --- |
| 타입 | Dropdown — 소식 / 일정 / 공지 (선택에 따라 §2.3 입력 폼이 분기, 기본값 소식) |
| 연결 아티스트 | Dropdown — 그룹 선택 |
| 공식 출처 | 토글 — 공식 제공 뱃지 표기 (소식·일정만 노출, 공지는 항목 자체 미노출) |

### 2.3 타입별 입력 폼

#### A. 소식

| 항목 | 필수 | 형식 |
| --- | --- | --- |
| 제목 | 필수 | 한국어·영어·일본어, 각 50자 |
| 본문 | 필수 | 한국어·영어·일본어 위지윅, 각 5,000자 |
| 이미지 | 선택 | 최대 10장. 첫 번째 이미지가 대표 썸네일로 사용됨(별도 썸네일 등록 없음) |
| 연관 콘텐츠 | 선택 | 최대 3건 — 각 행: 콘텐츠 타입 + 콘텐츠명(단일, 50자) + URL |

- 게시일은 작성 시 입력하지 않는다. [게시] 누른 날짜가 게시일이 되며, 재게시해도 최초 게시일이 유지된다([CEB-BO-INF-000] §4.2). 폼에는 "게시일은 [게시] 버튼을 누른 날짜로 자동 기록됩니다. (재게시 시 최초 게시일 유지)" 안내만 표시한다.
- 이미지: 클릭 또는 드래그로 등록(PNG·JPG·WebP). 등록한 순서대로 정렬되며, **첫 번째 이미지가 대표 썸네일**(앱 카드 등)로 사용된다. 개별 이미지는 [X]로 제거할 수 있고, 10장을 채우면 추가 영역이 사라진다.
- 연관 콘텐츠: [콘텐츠 추가]로 행을 추가하고 행별 [X]로 삭제한다. **3건을 모두 채우면 [콘텐츠 추가] 버튼이 비활성**된다(토스트가 아니라 버튼 비활성으로 일관). 콘텐츠 타입은 유튜브·X·인스타그램·스포티파이·일반 5종이며, '일반'은 타입에 없는 URL용이다. 콘텐츠명은 단일 텍스트(다국어 아님)이고, 썸네일은 입력한 URL에서 자동 추출(운영자 미관리)한다.

#### B. 일정

| 항목 | 필수 | 형식 |
| --- | --- | --- |
| 일정명 | 필수 | 한국어·영어·일본어, 각 50자 |
| 날짜 | 필수 | 날짜 선택 |
| 시간 | 필수 | 시간 선택 |
| 장소 | 선택 | 구글 장소 검색, 100자 |

- 일정에는 본문·이미지·게시일·부제·썸네일 입력이 없다. 일시(날짜+시간)는 이벤트 일자이며 게시일과 별개다.
- 장소: 검색어를 입력하면 구글 장소를 제안하고, **제안 목록에서 선택한 장소명을 그대로 사용**한다(운영자가 임의 텍스트로 직접 편집하지 않음). 입력칸을 비우면 선택이 해제된다.

#### C. 공지

| 항목 | 필수 | 형식 |
| --- | --- | --- |
| 제목 | 필수 | 한국어·영어·일본어, 각 50자 |
| 본문 | 필수 | 한국어·영어·일본어 위지윅, 각 5,000자 |
| 대표 이미지 | 선택 | 1장 (PNG·JPG·WebP) |
| CTA 버튼 | 선택 | 라벨(한국어·영어·일본어, 각 30자) + 링크 URL(단일) |

- 공지는 공식 출처 항목이 없다. 게시일은 소식과 동일하게 [게시] 누른 날짜로 자동 기록되며, 재게시 시 최초 게시일을 유지한다.
- CTA 버튼: 라벨과 링크를 함께 입력하면 앱 공지 상세에 버튼으로 노출된다. 라벨·링크 중 하나만 입력하면 미노출 처리한다.

> 시각적 스타일은 프로토타입 참조

### 2.4 게시·푸시 안내

[게시]를 누르면 게시 확인 모달([CEB-BO-INF-101-MD-PUBLISH])에서 게시 여부만 확인한다. **게시 자체는 푸시를 발송하지 않는다.** 푸시 알림이 필요하면 [CEB-BO-APP-302] 알림 작성 화면에서 별도로 작성·발송하며, 딥링크로 해당 소식·일정·공지를 연결한다([CEB-BO-INF-000] §4.6).

## 4. 규칙·로직

### 4.1 권한

- 권한 그룹별 읽기·쓰기·삭제 범위는 [CEB-BO-SYS-102] 권한 관리 그룹 설정을 따른다.
- 작성은 쓰기 권한 보유 그룹만 진입·저장할 수 있다. 권한이 없으면 [CEB-BO-INF-101] 리스트에서 [작성하기] 버튼이 미노출되어 본 화면에 진입할 수 없다.

### 4.2 다국어 게시 검증

- [게시] 시 소식·공지의 제목·본문, 일정의 일정명은 한국어·영어·일본어를 모두 입력해야 한다. 1개라도 빈 칸이면 [게시]가 비활성이며, 비활성 상태에서 게시 시도 시 차단 토스트를 노출한다.
- 미입력 언어가 있으면 해당 언어 탭에 미입력 표시를 노출한다.

### 4.3 타입별 게시 필수 검증

| 타입 | 게시 필수 항목 |
| --- | --- |
| 소식 | 제목·본문(각 3언어) |
| 일정 | 일정명(3언어), 날짜, 시간 |
| 공지 | 제목·본문(각 3언어) |

- 소식·공지의 **게시일은 게시 필수 항목이 아니다.** 작성 시 입력하지 않고 [게시] 누른 날짜로 자동 기록되며, 재게시 시 최초 게시일을 유지한다.
- 이미지·연관 콘텐츠·장소·대표 이미지·CTA는 모두 선택 항목이며 게시 필수가 아니다.

### 4.4 URL 검증

- 연관 콘텐츠 URL·CTA 링크는 올바른 URL 형식이어야 한다. 형식 오류 시 해당 입력에 인라인 에러를 노출한다.

### 4.5 임시저장

- [임시저장]은 미완성 상태에서도 항상 가능하다. 임시저장 시 상태는 임시저장으로 기록되고 앱에 노출되지 않는다.
