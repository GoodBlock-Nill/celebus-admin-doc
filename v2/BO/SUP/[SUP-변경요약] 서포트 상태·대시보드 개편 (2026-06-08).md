## 1. 한 줄 요약

> 서포트 이벤트의 **상태 모델·버튼·대시보드**를 운영 의도에 맞게 정리했습니다. 3가지: ① **강제 종료 = 모집중 전용** ② **대시보드 = 상태별 개별 카드** ③ **모집대기 상태 신설**(게시 후 시작 전 구간 분리).

세 변경 모두 **프로토타입과 문서를 함께** 맞췄습니다.

## 3. 핵심 개념 — 8상태 라이프사이클 + 상태별 버튼

```
임시저장 ─[게시]→ 모집대기 ─(시작일시 도달·서버 자동)→ 모집중
모집중 ┬─(누적 응원 ≥ 목표·자동)→ 달성 ┬─[집행 시작]→ 집행중 ─[결과물 등록·완료]→ 완료
       │                              └─[집행 취소]→ 집행취소 (전액 반환)
       └─(마감 + 미달성·자동)→ 미달성종료 (전액 반환)
모집중 ─[강제 종료]→ 미달성종료 (전액 반환)
집행중 ─[집행 취소]→ 집행취소 (전액 반환)
```

**상태별 버튼·노출·수정 매트릭스**

| 상태 | 앱 노출 | 버튼 | 수정 범위 |
| --- | --- | --- | --- |
| 임시저장 | 미노출 | 게시 / 삭제 | 전 항목(그룹 제외) |
| **모집대기**(신규) | **미노출** | **수정 / 삭제** | **전 항목**(목표·기간 포함, 그룹 제외) |
| 모집중 | 노출·응원 | **강제 종료** | 이름·설명·이미지·홈카드·유의사항(목표·기간 잠금) |
| 달성 | 응원 차단 | 집행 시작 / 집행 취소 | 읽기전용 |
| 집행중 | 진행중 | 결과물 등록·완료 / 집행 취소 | 읽기전용 |
| 완료 · 미달성종료 · 집행취소 | 결과/반환 표시 | 없음 | 읽기전용 |

> 강제 종료(모집중·아직 미달성) → **미달성종료**로 귀결되는 게 의미상 맞고, 집행 단계(달성·집행중) 중단은 **집행 취소**(→집행취소)가 전담. 강제 종료·집행 취소 모두 **전액 반환**.

## 4. 디자이너가 알아야 할 것

### 대시보드 (리스트 [SUP-101])
- 상태별 **개별 카드**를 라이프사이클 순으로 한 줄 배치: 임시저장 · **모집대기** · 모집중 · 달성 · 집행중 · 완료 · 미달성종료 · 집행취소
- 카드 클릭 = 해당 상태 단일 필터(토글). "종료" 묶음·임시저장 제외 폐지
- 상태 배지 색: 임시저장(연회색) · **모집대기(하늘색)** · 모집중(초록) · 달성(남색) · 집행중(주황) · 완료(진회색) · 미달성종료·집행취소(연분홍)

### 모집대기 상태 (신규)
- 게시 완료·시작일시 전 **운영자 전용 대기 상태**. **앱에 노출되지 않음**(시작일시 도달 시 첫 노출)
- 상세 헤더 버튼 = [수정]·[삭제]. 통계 카드 미표시(응원 0건)

### 게시 흐름
- [게시]는 **모든 필수값 입력 시에만** 활성. 게시하면 모집대기 → 시작일시에 자동 모집 시작

## 5. 개발자가 알아야 할 것

### 상태 enum (8상태)
`임시저장 · 모집대기 · 모집중 · 달성 · 집행중 · 완료 · 미달성종료 · 집행취소`

### 동작 규칙
| 항목 | 규칙 |
| --- | --- |
| 게시 | 임시저장 → **모집대기**(모집중 아님). **필수값 전부 입력** 시에만 가능 |
| 모집 시작 | 모집대기 → 모집중 = **서버 자동(시작일시 도달)**. 운영자 버튼 없음. 이 시점에 앱 첫 노출 |
| 모집대기 수정 | 전 항목(목표·기간 포함, 그룹 제외). 저장 시 필수값 충족 필요 |
| 강제 종료 | **모집중 전용** → 미달성종료, 전액 자동 반환 |
| 집행 취소 | 달성·집행중 → 집행취소, 전액 자동 반환 |
| 집행 시작 | 달성 → 집행중. 응원 덕력 집행 사용(완료 시 반환 없음) |
| 삭제 | **임시저장·모집대기**만(응원 0건·반환 불필요). 모집중~ 은 삭제 불가 |
| 반환 | 미달성종료·집행취소·강제 종료 시 **전액·서버 자동** |

### 필수값 (게시 조건)
이벤트명·설명(한/영/일) · 그룹 · 목표 응원량 · 시작/마감일시 · 대표 이미지 · 홈 카드 이미지 · 홈 카드 타이틀(한/영/일)
