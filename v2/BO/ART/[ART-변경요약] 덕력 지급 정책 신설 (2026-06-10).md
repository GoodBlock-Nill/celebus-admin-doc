## 1. 한 줄 요약

> 덕력관리에 **[CEB-BO-ART-401-POLICY] 덕력 지급 정책** 탭을 신설하여 **아티스트 그룹별 자동 적립 활동의 덕력 지급량·사용 여부**를 설정한다. **신규 아티스트 생성 시 권장값으로 기본 정책을 자동 생성**해 '미설정' 상태가 발생하지 않게 한다.

---

## 2. 개발자 결정 요청 답변

| 질문 | 답변 |
| --- | --- |
| 정책 미설정 시 미지급? 지급? | **'미설정' 상태를 두지 않는다.** 신규 아티스트 생성 시 권장값(T1 5/T2 25/T3 75·스트릭 200/500/1,000)으로 기본 정책 자동 생성. 기존 아티스트는 마이그레이션으로 권장값 정책 일괄 생성(백엔드). 따라서 정책 부재 미지급 발생 안 함 |
| BO 정책 설정 기능 | 덕력관리 4번째 탭 [CEB-BO-ART-401-POLICY] 신설 — 그룹 선택 → 자동 적립 활동 매트릭스(지급 덕력·사용 토글) |

## 4. 디자이너가 알아야 할 것

- **덕력관리 탭 3개 → 4개**: 랭킹 시즌 설정 / 덕력 랭킹 / 덕력 내역 / **덕력 지급 정책**.
- **지급 정책 탭**: 그룹 선택 드롭다운 + [권장값 적용]/[저장] + 매트릭스(활동·티어 배지·권장값(읽기)·지급 덕력 입력·사용 토글) + 마지막 수정 정보. 권장값과 다른 입력은 강조.
- 신규 아티스트도 항상 9개 활동 행 노출(빈 상태 없음).

---

## 5. 개발자가 알아야 할 것

- 정책 단위 = 아티스트 그룹 × 자동 적립 활동. 각 행 {지급 덕력(0 이상 정수), 사용 여부}. 미사용 시 미지급.
- **신규 아티스트 생성 시 권장값 기본 정책 행 자동 생성**(사용 ON). 기존 아티스트는 일괄 마이그레이션 필요(Open Item).
- Quest 완료·게임 참여(PM·ST)는 콘텐츠별 직접 입력 유지 → 정책 매트릭스 제외.
- 출석·일일미션·스트릭의 아티스트별 덕력 지급량 SSOT = 본 정책. 일일미션 관리([CEB-BO-DLY-101])는 미션 풀·하루 제시 수 담당.
- 프로토타입 정합:
  - `artists/duk/page.tsx`: 4번째 탭 '덕력 지급 정책' 추가
  - `artists/duk/_components/PolicyTab.tsx`(신규): 그룹 선택 + 매트릭스·변경 감지·[권장값 적용]·[저장] 확인
  - `mock/duk.ts`: `DUK_POLICY_ACTIVITIES`(9종)·`DukGroupPolicy`·`createDefaultDukPolicy`·`getDukPolicy`·`dukPolicies` 시드
