1. 한 줄 요약

서포트 이벤트의 상태 모델·버튼·대시보드를 운영 의도에 맞게 정리했습니다. 3가지: ① 강제 종료 = 모집중 전용 ② 대시보드 = 상태별 개별 카드 ③ 모집대기 상태 신설(게시 후 시작 전 구간 분리).

세 변경 모두 프로토타입과 문서를 함께 맞췄습니다.

2. 무엇이 바뀌었나 (Before → After)

#구분BeforeAfter
①강제 종료 노출달성·집행중에도 노출(오류)모집중 전용. 집행 단계 중단은 [집행 취소]가 전담
②대시보드 카드5장(완료 별도·미달성종료+집행취소 묶음·임시저장 제외)상태별 개별 카드(라이프사이클 순)
③게시 후 ~ 시작 전게시 즉시 모집중 → "모집중인데 미노출" 모순모집대기 상태 신설(앱 미노출), 시작일시 도달 시 자동 모집중

3. 핵심 개념 — 8상태 라이프사이클 + 상태별 버튼

임시저장 ─[게시]→ 모집대기 ─(시작일시 도달·서버 자동)→ 모집중
모집중 ┬─(누적 응원 ≥ 목표·자동)→ 달성 ┬─[집행 시작]→ 집행중 ─[결과물 등록·완료]→ 완료
       │                              └─[집행 취소]→ 집행취소 (전액 반환)
       └─(마감 + 미달성·자동)→ 미달성종료 (전액 반환)
모집중 ─[강제 종료]→ 미달성종료 (전액 반환)
집행중 ─[집행 취소]→ 집행취소 (전액 반환)

4. 디자이너가 알아야 할 것

대시보드 (리스트 [SUP-101])

  • 상태별 개별 카드를 라이프사이클 순으로 한 줄 배치: 임시저장 · 모집대기 · 모집중 · 달성 · 집행중 · 완료 · 미달성종료 · 집행취소
  • 카드 클릭 = 해당 상태 단일 필터(토글). "종료" 묶음·임시저장 제외 폐지
  • 상태 배지 색: 임시저장(연회색) · 모집대기(하늘색) · 모집중(초록) · 달성(남색) · 집행중(주황) · 완료(진회색) · 미달성종료·집행취소(연분홍)

모집대기 상태 (신규)

  • 게시 완료·시작일시 전 운영자 전용 대기 상태. 앱에 노출되지 않음(시작일시 도달 시 첫 노출)
  • 상세 헤더 버튼 = [수정]·[삭제]. 통계 카드 미표시(응원 0건)

게시 흐름

  • [게시]는 모든 필수값 입력 시에만 활성. 게시하면 모집대기 → 시작일시에 자동 모집 시작
