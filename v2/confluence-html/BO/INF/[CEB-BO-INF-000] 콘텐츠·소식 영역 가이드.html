1. 개요

소식·일정(INF) 영역은 아티스트의 소식·일정·공지를 운영자가 등록·관리하는 영역이다. 등록한 콘텐츠는 앱 [CEB-INF-101] 정보 피드(통합 타임라인 + 캘린더)와 [CEB-INF-201] 소식 상세에 노출된다. 운영자가 직접 작성·게시한다.

2. 화면 목록

2-1. 화면 ID 체계 (INF 영역)

상위 화면 번호에 접미사를 붙여 하위·부속·모달 화면을 구분한다.

접미사의미예시
  • 작성과 수정을 별도 문서로 분리한다. 작성은 [CEB-BO-INF-101] 리스트의 [작성하기]로 진입(101-CREATE), 수정은 [CEB-BO-INF-201] 상세의 [수정]으로 진입(201-EDIT)한다.
  • 완료는 모두 토스트로 안내한다. 별도의 "완료 모달"(다른 영역의 -MD-COMPLE류)은 두지 않는다. 작업 전 사용자에게 확인을 받는 확인 모달(게시·재게시·보관·삭제·취소)만 별도 문서로 둔다.

3. 권한

  • 권한 그룹별 읽기·쓰기·삭제 범위는 [CEB-BO-SYS-102] 권한 관리 그룹 설정을 따른다.
  • 소식·일정·공지의 작성·수정·게시·보관·삭제는 쓰기 권한 보유 그룹만 수행한다.

4. 영역 고유 정책

4.1 콘텐츠 타입 (3종)

타입설명앱 노출
소식아티스트 뉴스·소식정보 피드 타임라인 + 소식 상세
일정콘서트·팬미팅·방송 등 일정정보 피드 캘린더 + 타임라인 + 일정 상세
공지운영 공지·중요 안내정보 피드 상단 고정 배너 + 공지 상세

  • 공통 필드: 연결 아티스트(그룹), 상태.
  • 게시일은 소식·공지 작성 시 입력하지 않는다. [게시] 버튼을 누른 날짜가 게시일이 되며, 재게시해도 최초 게시일이 유지된다(§4.2).
  • 연관 콘텐츠의 콘텐츠 타입(5종): 유튜브·X·인스타그램·스포티파이·일반(타입에 없는 URL인 경우 선택). 콘텐츠명은 단일 텍스트로 다국어 입력을 받지 않는다.

  • 연관 콘텐츠의 썸네일은 운영자가 관리하지 않으며, 입력한 URL에서 자동 추출한다.
  • 일정의 장소는 구글 장소 검색에서 선택한 장소명을 그대로 사용하며, 운영자가 임의 텍스트로 직접 편집하지 않는다. 일정에는 부제·썸네일 입력이 없다.
  • 일정의 장소·소식의 연관 콘텐츠·공지의 대표 이미지·CTA 버튼은 앱 디자인 정합 필드다.

4.4 공식 출처 플래그

  • 소속사/아티스트 공식 채널을 통해 제공된 정보임을 표기하는 플래그.
  • 게시 시 앱에서 "공식 제공" 뱃지(일정) / "[공식 제공]" 태그(소식)로 노출된다.
  • 출처 신뢰성 강조 목적이며 독점 의미는 없다. (앱 [CEB-INF-101] 정합)

4.6 푸시 알림 (별도 알림 영역에서 발송)

  • 소식·일정·공지의 게시·재게시는 푸시를 발송하지 않는다. 게시 모달은 게시 여부만 확인한다.
  • 푸시 알림이 필요하면 [앱 운영 > 알림] 작성 화면([CEB-BO-APP-302])에서 별도로 작성·발송하며, 딥링크로 해당 소식·일정·공지를 연결한다.
  • 발송 대상·발송 시점·다국어 메시지·채널(기본/푸시) 규격은 모두 알림 영역([CEB-BO-APP-302])을 단일 기준으로 따른다(소식 영역은 별도 푸시 옵션을 두지 않는다).

4.7 리스트 기본 필터·정렬·페이지 규칙 (공통)

소식·일정 리스트([CEB-BO-INF-101]) 첫 진입·필터·정렬·페이지 동작의 공통 기준이다.

  • 첫 진입 시 타입 탭은 소식, 상태 필터는 전체로 시작한다(특정 상태로 고정하지 않음).
  • 상단 상태 카운터(게시/임시저장/보관)를 클릭하면 해당 상태로 필터링되고, 같은 카운터를 다시 클릭하면 전체로 해제된다(토글).
  • 타입 탭을 전환하면 상태 필터·검색어가 초기화되고 1페이지로 이동한다(그룹 필터는 유지).
  • 정렬: 1차 게시일(일정은 이벤트 일시) 내림차순, 동일 값일 때 2차 최근 등록·수정 일시 내림차순으로 보정한다. 사용자 변경 불가.
  • 필터·검색어·탭 변경 시 1페이지로 이동하며, 결과가 현재 페이지 수보다 적으면 마지막 페이지로 보정한다. 페이지당 10건.
