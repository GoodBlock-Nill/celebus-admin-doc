1. 한 줄 요약

BIVE(디지털 굿즈) 획득 덕력을 BIVE 6등급별 차등 지급으로 구현(명세화)했습니다. 덕력 지급 정책의 "디지털 굿즈 획득" 1행을 6등급 행으로 분리하고, BIVE 민팅(획득) 시 발행 BIVE의 등급을 조회해 해당 등급 덕력을 자동 적립(귀속=굿즈의 아티스트)하는 로직을 명세했습니다.

기존: 단일 75DUK + "등급별 차등 가능"이라는 정책 문구만 있고, 등급별 설정 UI·민팅→덕력 연결이 모두 부재.

3. 핵심 개념

  • BIVE 등급은 6종 고정(Event/Normal/Special/Wicked/Next/Final), BIVE 개별 단위({아티스트} {등급}-{등급번호}). SSOT=[CEB-BO-004].
  • BIVE 민팅(획득) 시점에 발행된 BIVE의 등급을 조회 → 굿즈 아티스트 그룹의 덕력 지급 정책에서 해당 등급 덕력(사용 ON 시)을 자동 적립한다.
  • 사용 여부: 등급별 사용/미사용 토글 — 미사용 등급은 해당 그룹에서 미적립.
  • 귀속: 굿즈의 아티스트(콘텐츠 귀속, 자동) — 회원의 선택 아티스트와 무관.
  • 권장값은 희귀도 추정 오름차순(Normal<Event<Special<Wicked<Next<Final)의 기획 제안값이며, 그룹·등급별로 운영자가 자유 조정한다.

4. 디자이너가 알아야 할 것

  • 덕력 지급 정책([CEB-BO-ART-401-POLICY]): 정책 매트릭스에 "디지털 굿즈 획득"이 6개 행(디지털 굿즈 획득 (Normal) ~ (Final))으로 노출. 각 행에 권장값·지급 덕력 입력칸·사용여부 토글. [권장값 적용] 시 6등급 권장값(50/75/100/200/350/500) 일괄 채움.
  • 프로토타입 덕력 지급 정책 탭은 활동 행 구조를 재사용하므로 6등급이 자동으로 6행 렌더(별도 UI 변경 없음).

5. 개발자가 알아야 할 것

  • 정책 데이터: 디지털 굿즈 획득이 등급별 활동 키 6종(goods_acquire_normal···_final)으로 분리. 각 키 = 1행(지급 덕력·사용 여부). 프로토타입 mock/duk.ts DUK_POLICY_ACTIVITIES 정합.
  • 민팅 발행 로직([CEB-BO-BIVE-FLOW] §5-3·§5-3-1):
    • WEIGHTED(확률 1개 발행): 발행 직후 해당 BIVE 등급 덕력 적립.
    • FIXED(등록 BIVE 동시 N개 발행): 발행된 각 BIVE 등급별로 합산 적립.
    • 적립 대상 = 사용 ON 등급만. 귀속 = 굿즈의 아티스트.
  • 적립 시점: BIVE NFT 발행 직후. 그룹 정책 조회 → 등급 매핑 → 덕력 적립 → 활동 로그.
