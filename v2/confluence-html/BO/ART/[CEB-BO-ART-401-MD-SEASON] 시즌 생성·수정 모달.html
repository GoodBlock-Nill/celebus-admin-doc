1. 화면 목적

운영자가 시즌을 신규로 등록하거나 기존 시즌의 시즌명·기간(연도·월)을 수정하는 모달이다. 생성·수정 두 모드를 한 모달에서 처리하며, 모드별로 입력 가능 필드와 기본값이 다르다.

  • 누가: 덕력 운영 권한이 있는 백오피스 관리자
  • 왜: 그룹별 1개월 운영 단위 시즌 정보를 등록·갱신해야 정산·랭킹·보상이 시작됨
  • 결과: 저장 시 시즌 리스트·시즌 상세 화면에 즉시 반영

2.3 입력 필드 — 모드별 동작

필드컨트롤생성 모드수정 모드
그룹선택 메뉴 (활성 그룹 5종 중 1종)활성 — 운영자가 선택수정 불가 (회색 텍스트로 표시)
시즌 (연도·월)연도 선택 + 월 선택 두 메뉴활성 — 운영자가 선택"예정"일 때만 활성. "진행중"·"종료"는 수정 불가

시즌 기간자동 산출 안내수정 불가 — "{연}.{월}.01 00:00 ~ 말일 23:59 (자동)" 표시동일

2.4 시즌 1개월 운영 단위 정책

  • 시즌 기간은 연도·월 선택으로 결정되며, 선택한 달의 1일 00:00 ~ 말일 23:59 (1개월)로 자동 산출된다(자유 입력 폐지)
  • 모달 하단에 "시즌 기간: {연}.{월}.01 00:00 ~ 말일 23:59" 안내가 표시되어 운영자가 기간을 사전 확인 가능
  • 연도·월 변경 시 기간 안내·자동 제안 시즌명이 즉시 갱신 — 시즌명은 3언어 템플릿으로 동시 제안(한국어 "{그룹} {연}.{월} 시즌" / 영어 "{group} {YYYY}.{MM} Season" / 일본어 "{group} {YYYY}.{MM} シーズン"), 각 언어 수정 가능
  • 연도 옵션 범위: 현재 연도부터 +2년까지 제공한다(수정 모드는 기존 시즌 연도도 포함). 월은 1~12월.
  • 생성 직후 시즌 상태 판정: 선택한 월이 현재 월이면 진행중, 미래 월이면 예정으로 등록된다(지난 월은 §7에서 차단).

2.5 수정 모드 — 기간(연도·월) 변경 제약

  • 시즌이 "진행중" 또는 "종료" 상태일 때 기간(연도·월)을 변경하면, 기존 보상·정산 데이터와 매칭이 어긋나 운영 무결성에 영향을 준다
  • 따라서 "진행중"·"종료" 시즌은 시즌명만 변경 가능, 연도·월은 회색 처리로 수정 불가 안내
  • "예정" 시즌은 연도·월 자유 변경 허용 (보상 설정이 아직 운영되지 않음)

2.6 인라인 검증 메시지

운영자가 어떤 필드가 실패인지 즉시 파악할 수 있도록 필드별 인라인 에러 메시지를 표시한다. 각 필드는 포커스 후 첫 이탈 시점부터만 에러를 노출하여 모달 진입 직후 빈 폼에서 에러가 폭주하는 현상을 회피한다.

필드인라인 에러 메시지
시즌명미입력 언어가 있으면 해당 언어 탭에 빨간 점 + "모든 언어의 시즌명을 입력하세요" / 50자 초과 시 입력 자체가 차단 + "50자 이하로 입력하세요"
지난 월선택 연·월이 현재 월보다 이전: "지난 월은 시즌을 생성할 수 없습니다. 현재 또는 이후 월을 선택하세요."
동일 월 시즌 존재같은 그룹·같은 월에 시즌이 있으면 상태별: 진행중 "이 달에는 이미 진행중인 시즌이 있습니다." / 예정 "이 달에는 이미 예정된 시즌이 등록돼 있습니다." / 종료 "이 달에는 이미 종료된 시즌이 있습니다."

3. 화면 내 기능설명

운영자가 이 모달에서 할 수 있는 동작:

  1. 신규 시즌 등록 — 그룹·연도·월 선택 + 시즌명(자동 제안·수정 가능) 후 저장
  2. 시즌명 수정 — 모든 상태 시즌에서 가능
  3. 기간(연도·월) 수정 — "예정" 시즌에 한해 가능
  4. 시즌 기간 자동 확인 — 선택 월의 1일~말일(1개월)이 자동 산출되어 표시
  5. 저장·취소 — 푸터 액션으로 처리

4. 규칙·로직

4.1 생성 모드 진입

  1. 랭킹 시즌 설정에서 [+ 신규 시즌] 클릭 → 본 모달 열림
  2. 모달 타이틀 "신규 시즌 등록" + 연도·월은 현재 연·월 기본값, 시즌명은 자동 제안
  3. 그룹·연도·월 선택 가능 / 시즌 기간은 선택 월의 1일~말일로 자동 산출, 시즌명은 선택에 맞춰 자동 제안(수정 가능)

4.2 수정 모드 진입

  1. 시즌 상세 상단 [수정] 클릭 → 본 모달 열림
  2. 모달 타이틀 "시즌 정보 수정" + 기존 값 자동 채움
  3. 그룹은 회색·수정 불가
  4. 연도·월은 시즌 상태별 분기:
    • 예정 시즌: 활성
    • 진행중·종료 시즌: 회색·수정 불가
  5. 시즌명은 모든 상태에서 활성

4.3 입력 → 검증 → 저장

  1. 운영자가 필드 입력
  2. 각 필드 포커스 이탈 시 인라인 검증 메시지 노출 (touched 이후만)
  3. [저장] 클릭 시 전체 검증 재실행:
    • 시즌명 한국어·영어·일본어 3언어 모두 입력, 각 1~50자
    • 연도·월 선택 (기본값 제공, 항상 유효)
    • 같은 그룹·기간 중복 시즌 없음
  4. 검증 통과 시:
    • 저장 처리
    • 모달 닫기
    • 토스트 "시즌이 저장되었습니다."
    • 부모 화면 자동 갱신
  5. 검증 실패 시:
    • 첫 오류 필드로 포커스 이동
    • 인라인 에러 메시지 노출

4.4 취소

  1. [취소] 클릭 또는 모달 외부 클릭 또는 [X] 클릭
  2. 입력값 모두 폐기 후 모달 닫기 (확인 모달 없음 — 시즌 저장 모달은 가벼운 입력 단위)

4.5 권한별 동작

  • 권한은 [CEB-BO-SYS-102] 권한 관리 그룹 설정에 따른다
  • 쓰기 권한 없으면 모달 자체가 호출되지 않음 (부모 화면의 [+ 신규 시즌]·[수정] 버튼 미노출)

7. 에러·예외 상황

7.1 입력 검증

상황동작 (메시지)
그룹 미선택 (생성 모드)[저장] 차단. "그룹을 선택하세요."
시즌명 일부 언어 미입력[저장] 차단. 미입력 언어 탭 빨간 점 + "모든 언어의 시즌명을 입력하세요."
시즌명 공백만 입력[저장] 차단. 해당 언어 빈 값 처리. "모든 언어의 시즌명을 입력하세요."
시즌명 50자 초과입력 자체 차단 + "50자 이하로 입력하세요." (언어별 각 50자)
연도·월 미선택[저장] 차단 (기본값 제공으로 정상 상황에선 미발생)

7.2 지난 월 차단

상황동작 (메시지)
선택 연·월이 현재 월보다 이전[저장] 차단. "지난 월은 시즌을 생성할 수 없습니다. 현재 또는 이후 월을 선택하세요."

시즌은 현재 월(진행중) 또는 이후 월(예정)로만 생성한다. 진행중·종료 시즌 수정은 연·월이 읽기 전용이므로 본 검사 제외.

7.3 동일 월 시즌 존재 (상태별 안내)

시즌은 그룹×월 1:1이다. 선택한 월에 같은 그룹의 시즌이 이미 있으면 상태별 메시지와 함께 [저장] 차단:

상황동작 (메시지)
같은 그룹·같은 월에 진행중 시즌 존재"이 달에는 이미 진행중인 시즌이 있습니다."
같은 그룹·같은 월에 예정 시즌 존재"이 달에는 이미 예정된 시즌이 등록돼 있습니다."
같은 그룹·같은 월에 종료 시즌 존재"이 달에는 이미 종료된 시즌이 있습니다."

7.4 진행중 1개 — 미래 예정 생성 허용

  • 진행중 시즌은 그룹당 현재 월 1개로 자연히 제한된다(현재 월은 §7.3 동일 월 검사로 중복 차단, 다른 달은 진행중이 될 수 없음).
  • 진행중 시즌이 있어도 미래 달의 '예정' 시즌은 미리 생성할 수 있다(월이 겹치지 않으므로 허용). 과거의 "진행중 있으면 신규 생성 전면 차단" 규칙은 폐지.

7.5 차단 사유 단일 노출 (혼란 방지)

  • §7.2(지난 월)·§7.3(동일 월 시즌 존재)이 동시에 성립할 때 메시지를 함께 띄우지 않고 지난 월 > 동일 월(상태) 우선순위로 하나만 노출한다.
  • [저장] 차단 자체는 두 조건 중 하나라도 성립하면 동일하게 적용된다.
